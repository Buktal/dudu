# Console 管理权与 Desk 接待范围分离

2026-10-20，用户授权代理按推荐方案完成 Console 全部规划决策。本决定是授权下的设计选择，不表示用户逐项确认，亦不表示功能已经实现。它补齐 [ADR 0011](0011-enterprise-group-access.md) 留待后续的管理权限，不改变其中的接待范围规则。

初始企业管理员负责全企业员工生命周期、管理员任免及用户组创建；普通企业管理员只管理自己所属组的组名称、普通员工成员关系和渠道账号。普通员工没有 Console 权限。普通管理员的管理范围直接复用当前本企业组成员关系，初始管理员通过企业 initUserId 获得全企业管理权，不新增角色表、管理范围关联表或自定义权限配置。

只有初始管理员可以调整管理员身份及管理员的组成员关系。普通管理员可将本企业已启用的普通员工加入自己管理的组，但不能改变自己或其他管理员的成员关系，也不能修改员工密码、身份和状态；员工候选只展示必要的普通员工标识与姓名。账号换组要求同时有源组和目标组管理权。

此划分保留组内自主维护，又避免把能看到某员工的一组成员关系扩展成重置该员工密码、改变其其他组权限的全局能力。全体管理员全企业管理会突破既定分组意图；另一套可配置角色和管理组关系则增加当前没有必要的数据与授权机制。需要更多企业级管理员时应另立明确需求，不把普通管理员角色暗中提升为全企业管理。

每个 Console 请求重新校验持久员工、企业状态与当前角色，再计算管理范围，不能只依赖旧 JWT 的角色。无状态 JWT、Desk 多组接待与历史随渠道账号当前组可见的约定保持不变。

管理写命令在事务中先锁定本企业既有company行，再重新读取身份、角色与组关系并执行；同企业低频管理写按此串行化。它防止角色提升、组收权或账号换组与授权检查交错，不引入权限版本列或额外锁表。具体MP查询与通知约定见数据契约。

详细权限矩阵和首版行为见 [Console 规格](../design/dudu-console/README.md)；接口见 [数据契约](../design/dudu-console/data-contract.md)。
