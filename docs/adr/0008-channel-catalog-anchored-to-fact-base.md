# 渠道全量锚定事实库：19 渠道、HTTP 回调子形态、核验目录为全量基准

mock-pulse 从 2 渠道扩展到全渠道时，「所有渠道」「所有事件」没有天然定义——飞书官方事件类型数百个、知乎无推送、淘宝国内栈只有 TMC 长连接。决定：渠道接入范围 = 渠道事实库（`docs/research/channels/`）覆盖的 20 渠道中具备 HTTP(S) 回调形态的 19 个，其中淘宝取全球栈 HTTPS 回调形态并在渠道条目标注，知乎因无推送可 mock 排除；每渠道事件模板的「全量」= 事实库逐字核验过的事件目录，而非平台全目录；同渠道有多种接入体系时一律取 HTTP 回调子形态（飞书 Webhook、钉钉新 HTTP 密文、QQ Webhook Ed25519、Telegram Webhook），不做长连接模拟。消息/客服类事件做全字段描述，订单/审批/通讯录类载荷结构照旧高保真（保真度仍以 ADR-0001 为准）、字段描述从简

## Considered Options

- 平台全目录全量：被否，飞书/钉钉事件类型数百个，不可交付也无核验出处
- 仅消息/客服类事件：被否，放弃事实库已核验的订单/授权/通讯录事件价值
- 淘宝模拟 TMC 长连接、飞书/钉钉/QQ 做长连接模拟：被否，每个都是全新运行形态，成本/价值比不成立
- 知乎以拉取式 REST 桩接入：被否，mock-pulse 是回调模拟工具，拉取式没有可发方向（事实库保留结论）
