# 企业隔离、平级接待组与共享接待权限

2026-09-28 Server 规划确认：DUDU 面向多家企业，企业是成员权限及业务数据的隔离边界。每个员工 ID 唯一且固定属于一个企业 ID；昵称可以重复，不用于身份识别。员工由管理员创建。

2026-09-29 补充确认：企业由 DUDU 运营方创建，创建企业时同时初始化一个企业管理员账号。DuduAdmin 是运营方使用的管理后台，DuduConsole 是企业内部管理员工、接待组和渠道接入账号的控制台；不能据角色名称中的“管理员”授予 DuduAdmin 权限。

企业内采用平级接待组，员工可加入本企业的多个组。每个渠道接入账号只归属一个组，一个组可以负责多个接入账号，以明确账号的负责范围。分组对象是具体接入账号，例如一个微信公众号，而不是微信公众号这一渠道类型。当前不引入组层级、会话认领或独占负责人；有权看到会话的坐席都能回复，每条回复保留实际发送员工的身份。

企业管理员通过角色直接获得本企业全部组的权限，包括以后新建的组，不维护逐组成员关系。空组列表本身不表达全组权限：普通员工按其组成员关系授权，没有加入任何组时没有接待权限。管理员的全组权限仍受所属企业约束。

2026-09-30 补充确认：企业员工登录名在所属企业内唯一，跨企业允许同名；企业侧登录使用“企业编号＋登录名＋密码”，平台登录继续使用账号与密码。这样各企业可以保留默认 `admin` 登录名，由企业编号区分登录作用域。员工内部 ID 仍唯一且固定属于一家企业，昵称不参与登录身份判断。Desk 现有登录输入尚需在真实认证接入时同步增加企业编号，此决定不表示该界面已经实现。

## Considered Options

- 平级接待组与账号单组归属：选定，支持按职责组织接待并明确负责范围。
- 企业内登录名唯一：选定，允许不同企业使用同名账号；代价是企业登录需额外输入企业编号。全平台登录名唯一未采用，避免各企业争用常用登录名和默认管理员名称。
- 树形组织、账号多组归属：未采用，当前不需要层级，用户希望账号责任集中。
- 认领后独占回复：未采用，用户明确选择有权看到会话的坐席均可回复；个人对话分配留待后续需求。
