# 剧本按平台分组：每平台独立剧本，禁混写

测试剧本按平台分组：每个平台有自己独立的剧本（抖音剧本 / 企微剧本），禁跨平台混写——掺在一起 Mock 没有意义。以后想要穿插就多平台剧本并行跑（两条并发线），自然形成并发，不在组内造穿插。组是文件级归属：剧本目录下 `douyin/`、`wecom/` 各一组，步内 JSON 不冗余 `group` 字段；每步四行：渠道 / 事件名 / 发的内容 / 期待的回执（#3 + 追补，#4 落目录）

追补（#19 实施，2026-09-12）：文件级归属落得更彻底一档——剧本 JSON 顶层只写 `{id, name, steps}`，连 `channelId` 也不写，渠道单一源头就是子目录路径，读取时回填；每步落盘仅存 `{eventId, revision}` 引用，四行语义（渠道/事件名/发的内容/期待回执）在运行时由引用解析呈现，不复制载荷

## Considered Options

- 步内加 `group` 字段、目录平放：被否，组与文件一一对应时字段是冗余单源头破坏者
- 组内混排模拟并发：被否，失真且难断言；并发语义归执行层多组并行
