## 完成标准

Console正式前端连接真实Server和独立测试库，完成员工、用户组、渠道账号配置；实际Desk客户端按新范围读取数据。前端不以内置模拟登录或运行时假数据替代接口，开发失败如实展示。渠道协议用现有受控对拍和黄金向量验证；生产渠道账号申请、平台审核、生产凭据和外网端到端测试不作为首版交付必需前置，未执行的生产验证必须逐渠道注明。

范围限现有适配器。美团只在HTTP、80/8080且保留实际Host的入口验证；HTTPS-only部署目录明确不开放。OAuth授权流程、自动连通检测、渠道健康监控及新增协议不属于实施完成条件。

## 核心验收场景

| 场景 | 外部行为断言 |
| --- | --- |
| 初始管理员登录 | 使用企业ID/登录名/密码获取当前企业身份，能管理以后新建的组，无需显式成员行 |
| 普通管理员无组 | 可以登录/改自己的密码，业务范围为空，不能用空数组或缺失groupId访问全企业 |
| 普通员工/平台管理员登录Console | 明确拒绝；Desk原有console/user登录能力不变 |
| 员工创建与并发同名 | 员工ID/企业归属固定，企业内登录名大小写不敏感唯一；重复提交不创建两个员工，跨企业同名允许 |
| 初始管理员保护 | 自己不能被停用/降级，不能从重置他人密码接口绕过原密码；管理员恢复走已有Admin入口 |
| 员工停用与角色调整 | 保留历史发送者和成员关系；停用后下次请求拒绝并通知Desk重查；console降级user失去Console但仍按当前组接待 |
| 个人改密/退出 | 原密码错误不改库；成功清当前Console会话；退出不冒充服务端撤销其他token |
| 普通管理员管理成员 | 只能操作所管组的普通员工关系，不能改自己/其他console关系，不能更改员工密码/角色/状态 |
| 多组员工 | 单组移除不影响其他组；幂等添加/移除，不产生重复成员行 |
| 并发授权 | 以两个事务复现“普通员工同时被提升管理员”和“源组同时被收权/换组”；企业行锁后重新授权，禁止以旧角色/旧源组完成越权写入 |
| 跨企业/不可见对象 | 列表、候选、详情和写入统一受身份与范围约束，不泄漏他企存在性；脏关联不扩大权限 |
| 实际渠道目录 | 不出现bilibili可接入选项；公众号仅明文、企微仅agent、钉钉仅http_crypto；美团遵守部署限制 |
| 凭据写入与读回 | 请求按渠道白名单校验；列表/详情/异常/日志不含秘密；省略保持、clear明确清除，必需项清空整笔回滚 |
| 账号身份保护 | 拒绝已配置身份键变更；Telegram同Bot ID轮换、清除后仍保留botId，不能通过clear后换ID；无法验证的不透明授权按已声明限制记录 |
| 接收/发送准备 | 缺可选发送字段仍可保存合法接收配置，但明确显示缺项，不显示“在线/已接通” |
| WhatsApp创建 | 事务内取得ID并派生正确url，再校验/提交；失败不留半账号 |
| Telegram映射 | 输入不是任意URL；拒绝路径/查询/fragment注入；只写官方主机，响应/clear/缺项均使用botToken别名 |
| 渠道账号换组 | 普通管理员必须同时有源/目标权限；旧组失去全部历史访问，新组取得同一份历史，账号/访客/消息ID和条数不改变 |
| 通知与回滚 | 成员变更、员工状态/角色、账号变动在提交后发已有access-changed；回滚无业务残留和失实通知 |
| UI状态与键盘 | 真实加载/失败/空态、输入保留、重复提交禁用、确认与关闭、身份失效、键盘焦点可用；390/1280/1440宽验证 |

受控测试凭据只出现在测试fixture或测试库，不进入截图/日志/正式配置。HTTP响应恒200的应用错误和网络/代理失败分别验证。

## 检查与数据边界

- Console在其子项目根执行现有 `yarn check:all` 和 `yarn build`；Java在dudu-server根执行已有编译、相关单元与集成测试。只新增外部行为/风险用例，不为页面结构写镜像测试。
- 数据库只复用mysql-local，独立 `dudu_review_console_<用途>` 库、dudu_review用户，自建自删。禁止写开发库dudu、另起MySQL或Testcontainers。
- 方案没有业务表/列变化，Telegram的botId在现有JSON内派生；不安排无理由的迁移或历史迁移改写。若实施发现实际必须改持久结构，先说明与本契约的差异，再新增迁移并验证空库/升级，不默默改旧迁移。
- 渠道配置契约测试覆盖13种字段组合及限制，凭据不全、错误key、轮换/清除、Telegram别名与身份保护。受控HTTP回调覆盖各现有适配器，不要求测试fixture能证明真实生产平台授权。
- 页面实际检查需覆盖初始/普通/无组管理员及失败态；视觉沿用Admin，只验证Console新增页面，避免顺带改Admin或Desk。
- 规格阶段仅核对文档与GitHub关系；实施阶段实际检查结果以上方执行记录为准。
