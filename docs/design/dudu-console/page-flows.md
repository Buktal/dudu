# Console 页面与关键流程

2026-10-20，按用户授权由代理定稿，**未制作或声称用户验收交互原型**。本票从原型讨论调整为页面规格决策；实际交互与布局验证是实施完成条件。范围与权限见 [规格](README.md)，字段见 [契约](data-contract.md)

## 视觉与导航

沿用DuduAdmin现有品牌、Inter/系统中文字体、深浅主题、紧凑表单和管理布局；浅色背景#f6f8fb、正文#243345、品牌#f2785c、主操作#c74e32、边框#e1e7ef均取自其现有主题。实施时读取主题源码而非复制本说明作为新主题事实源。不增加装饰性概览、统计卡或新字体依赖

左侧导航为“员工”（仅初始管理员）、“用户组”、“渠道账号”；底部个人账号和退出。顶部显示企业名称与六位企业ID，不提供企业切换。默认初始管理员进入员工列表，普通管理员进入用户组；个人账号始终可访问

复用Admin的轻量hash路由思路和查询/提交交互原则，在Console内建立自己的路由构造与解析，不跨项目导入Admin平台业务。路由由一个模块构造，返回/关闭弹层清除对应参数，不手工散拼字符串

| 路由 | 页面与主要操作 |
| --- | --- |
| `#/login` | 企业ID、登录名、密码；显示真实错误，不做模拟登录 |
| `#/employees` | 登录名/姓名搜索、角色/状态筛选、分页、创建员工 |
| `#/employees?userId=<id>` | 员工侧栏：资料、当前组、改显示名称、角色、启停、重置密码；初始管理员保护就地说明 |
| `#/user-groups` | 可管理组列表；初始管理员可创建；普通管理员无组时给联系初始管理员的空态 |
| `#/user-groups?groupId=<id>` | 组详情：成员和渠道账号两页签；组名编辑、添加/移除成员、跳到组内新建账号 |
| `#/channel-accounts` | 按账号名、渠道、可管理组筛选，分页与创建 |
| `#/channel-accounts?accountId=<id>` | 账号侧栏：配置存在情况、只读回调地址、渠道准备说明、编辑及换组 |
| `#/account` | 个人身份、改密；不提供企业资料编辑 |

创建员工、创建组用带标题的Dialog；渠道配置字段较多，使用宽侧栏Sheet，窄屏切为全宽。列表详情通过URL保留当前位置，关闭返回原列表与筛选。初次登录不弹强制向导：每个空态提供当前权限内的下一步

## 核心流程

1. 初始管理员用企业ID登录，进入员工页。新建员工后显示“员工已创建”，可继续去用户组，不展示已保存密码
2. 创建用户组，进入组详情添加员工；未启用员工不在新增候选中。成员添加/移除后重取成员和组计数，Desk按事件重取接待范围
3. 从组详情“添加渠道账号”预填该组，选择实际可接入渠道。展示“回调配置”和“发送配置”两个业务分区，只呈现本渠道所需字段与限制
4. 保存账号后显示回调URL供复制及渠道侧准备说明，明确“参数已保存，请在渠道平台配置并验证”；接收/发送缺项分别展示，不出现“已连接/在线”
5. 有权员工登录Desk验证范围与收发。Console不嵌入聊天或代接待入口；地址没有部署配置时不猜测Desk Web URL
6. 换组时选择源、目标均有权的组，确认框明确历史可见性变化。成功后重取账号列表/详情和相关组计数；普通管理员权限被收回时下一次查询关闭不可见详情

普通管理员从组详情管理普通员工成员，不暴露员工管理页面。添加成员Dialog只展示必要名录与登录名，不包含密码、角色变更或其他组信息。不能把“添加成员”变成“新建员工”，缺少员工时提示联系初始管理员

## 表单与失败状态

- 输入保留草稿，搜索提交后应用；重置同时清理草稿与应用筛选并回第一页。失败显示重试，不把失败显示成“没有数据”。列表存在旧数据时明确失败状态，不冒充当前查询成功
- 提交期间禁用重复提交和关闭动作；服务端失败保留输入，成功后再关闭并刷新相关查询。密码和凭据提交成功立即清除本地明文输入，取消弹层也清除；秘密不放URL、storage、Redux持久区或toast
- 秘密已配置时显示“已配置”，空输入含义为保持不变；用户点“清除”才形成clear指令。接收必需字段不能被清空，错误落在该字段，禁止用一串星号充当原值提交
- 已配置的固定身份字段只读并提示换账号需新建；Telegram允许同Bot ID的token轮换，由后端强制前缀一致，不能把“字段可输入”解释为允许换绑
- 停用、角色撤销、重置他人密码和账号换组都有带对象名称及ID的确认；普通资料改名无需重复确认。自身改密要求原密码，成功清会话回登录
- 业务无权限时刷新身份与当前页，保留仍有权访问的其他导航；身份失效才清会话。跨企业/不可见对象使用统一不存在反馈
- 表单有可见label，错误关联输入，键盘可完成；Dialog/Sheet有标题、焦点管理和Escape行为。1280/1440桌面及390宽屏必须检查，窄屏表格允许有意义的横向滚动，不裁掉操作按钮

## 前端组织

保持Console已有Vite/React/shadcn(Base UI)/Yarn/Biome/Vitest栈；业务按account、employees、groups、channel-accounts组织，API负责请求、运行时响应校验和会话，组件承载查询/提交状态。字段定义由目录接口下发，不在13个页面分支里重复密码保留语义

可按需移用Admin的主题、品牌、QueryView、FilterBar、SubmitShell和请求取消/过期处理思路；它们目前不是共享包，不直接依赖Admin项目内部模块，也不先为两个前端做全仓组件抽象。开发沿用Vite `/api`同源代理，生产同源反代；不恢复旧的可见环境切换或新增认证依赖
