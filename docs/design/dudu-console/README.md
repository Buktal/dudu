# DuduConsole 首版实施规格

2026-10-20 定稿。用户确认首版范围和沿用 DuduAdmin 风格，随后授权代理“都去决策完，按推荐决策”。下文为该授权下的方案选择，不是逐项用户确认记录。**方案已定，业务功能尚未实现。**

仓库根相对路径用于文档；本目录是 Console 规格与数据契约的入口。[决策地图](https://github.com/Buktal/dudu/issues/119)及其 resolution comments 保存决策理由，本目录保存可供实施的规范性结果，不另建镜像地图。

## 目标与范围

从 Admin 已开通企业出发，初始管理员登录 Console，创建员工与平级用户组，分配成员，接入企业渠道账号；员工在 Desk 获得正确的接待范围。首版包含登录、退出、个人账号、员工、用户组与成员、渠道账号接入和换组。

企业资料维护、操作记录页面、资源概览、统计、质检、知识库、CRM、AI、计费不在首版范围。平台运营仍在 Admin，接待仍在 Desk。初始管理员不可在 Console 转让；账号恢复仍由 Admin 重置其密码。

## 权限矩阵

所有操作均限当前已认证企业；“初始管理员”还须是持久角色 console、启用且 company.initUserId 指向的本企业员工。

| 操作 | 初始企业管理员 | 普通企业管理员 | 普通员工 / 平台管理员 |
| --- | --- | --- | --- |
| 登录 Console、查看自己的账号、改自己的密码、退出 | 允许 | 允许 | 拒绝 Console |
| 查询全企业员工及员工详情 | 允许 | 不提供员工管理入口 | 拒绝 |
| 创建员工、编辑显示名称、启停、重置他人密码 | 允许，初始管理员有下述保护 | 拒绝 | 拒绝 |
| 任免其他企业管理员 | 允许 | 拒绝 | 拒绝 |
| 创建用户组 | 允许 | 拒绝 | 拒绝 |
| 查询组、组详情、修改组名 | 全企业组 | 仅当前所属组 | 拒绝 |
| 查看组内成员和账号 | 全企业组 | 仅当前所属组 | 拒绝 |
| 添加或移除普通员工组成员关系 | 全企业组 | 仅当前所属组 | 拒绝 |
| 修改自己或其他管理员的组成员关系 | 允许（初始管理员自动全组，不建成员行） | 拒绝 | 拒绝 |
| 新增渠道账号、编辑配置和密钥 | 全企业组 | 仅当前所属组 | 拒绝 |
| 渠道账号换组 | 源、目标均为本企业 | 源、目标均为当前所属组 | 拒绝 |

普通管理员没有所属组时可以登录并管理个人账号，业务列表为空，提示联系初始管理员分配组；空范围绝不代表全企业。普通管理员添加成员时，可查询本企业已启用普通员工的最小候选名录，不开放全企业员工详情、状态或密码操作。

服务端在每次请求重新检查企业、员工启用状态与当前角色，管理范围重新计算；companyId 来自身份，不接受客户端决定租户。对象跨企业或不可见时统一按不可见处理，不能通过差异错误枚举他企数据。

## 员工与个人账号

- 创建：登录名、显示名称和初始密码；初始角色为 user，状态为 1。初始管理员后续可提升为 console，再显式分配组。
- 登录名在企业内大小写不敏感且唯一，创建后不改；显示名称可改、允许重名。ID 和企业归属固定。
- 初始密码由管理员填写，复制按钮只针对当前尚未提交的输入，密码保存后不回显；由管理员自行通过现有途径交付，本轮不加邮件、短信或邀请系统。
- 普通员工和普通管理员可停用、恢复。停用保留成员、消息及发送者身份；恢复后按当前成员关系恢复权限。不做员工删除。
- 初始管理员不能被停用、降级或被 Console 重置密码。自己改密必须输入原密码；初始管理员遗失密码走 Admin 已有恢复入口。所有管理员都不能用“重置他人密码”绕过自己的原密码验证。
- 只有初始管理员能重置其他员工密码和改变其他员工角色。提升不自动加入全部组；降级仍可按组使用 Desk，但不再能使用 Console。
- 个人账号显示企业 ID/名称、员工 ID、登录名、显示名称与角色；个人页只提供改密和退出，显示名称由初始管理员在员工管理中维护（含自己的显示名称）。
- 新密码沿用 8–72 字符，密码不 trim；不引入强制首次改密、密码版本或 token 撤销表。改密成功后当前 Console 清会话并要求重新登录，不承诺其他已签发 token 立即失效。

## 用户组与成员

- 用户组平级，组名 1–100 字符；允许重名，选择器同时显示组 ID。允许空组，创建时无成员、无渠道账号。
- 初始管理员可创建组；有组管理权者可改名。首版不加组启停或删除，已有表无状态字段；后续需要撤组时另行设计账号归属与保留规则。
- 成员按单组添加/移除，操作幂等。只新增已启用员工；已停用的原成员仍可查看或移除，恢复员工不会丢失关系。
- 普通管理员只能添加/移除 role=user 的成员，不能触碰 console 员工（含自己）。初始管理员可以为其他管理员分配或收回组。
- 初始管理员自动全组，在组详情显示“初始管理员自动拥有权限”，不创建虚假成员行或允许移除。
- 不从单组页面提交“该员工全部组”，避免覆盖看不到的其他组关系。成员关系及账号换组必须在事务成功提交后通知 Desk 重查权限。

## 企业渠道账号

- 实际适配器及字段详见 [渠道字段](channel-fields.md)。新增时指定当前可管理组；同企业可有同渠道多账号，名称允许重复，以账号 ID 消歧。
- 接收必需参数必须齐全；发送参数允许暂未配齐，按最终字段计算并明确展示缺项。明确标为“发送参数未配齐”，不以保存成功表示接通或在线。
- 渠道类型创建后不变。显示名称和同一外部账号的凭据可维护；换成另一个真实外部账号必须新建记录，保留原账号的历史身份。
- 不增加独立外部账号标识或唯一索引，不把 appId、应用密钥或 externalAccountId 当成跨渠道通用账号身份。部分平台一个应用可授权多个账号，首版不宣称能自动识别重复真实账号。
- 凭据只写、响应只返回配置存在标记。编辑时留空保持原值，明确“清除”才发送清除指令；不能清除接收必需项使账号变成半配置状态。凭据不进入 Desk、日志或通用查询缓存。
- 换组前确认：历史随新组可见、旧组失去访问。只更新账号当前 groupId，不复制消息、访客或名片。普通管理员需同时管理源组和目标组。
- 首版不提供账号启停、删除、OAuth 向导、自动连通性检测或持久健康状态。若要停止外部来信，在渠道官方平台停用回调/撤回授权；Console 不宣称能远程完成这件事。已有记录保持可追溯。

## 实施约束与现状

复用现有 user、user_group、user_group_member、company_channel，无新增业务表或列、无外键、无新依赖。Console 接口及前端仍待开发；当前 Server 的仅部分服务写方法触发权限通知，不能假定批量方法和员工更新已自动覆盖。

现有未提交微信共享组件及 CompanyServiceImpl 等工作与本规划独立，不纳入本次变更。渠道事实优先核对 Server 实际实现，旧 Admin 设计草案与 ADR 0006 开头的过时错误码段不作为当前接口事实。
