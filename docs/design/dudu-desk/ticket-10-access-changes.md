[DuduDesk 对接 Spec：共享接待、访客名片与消息同步 #84](https://github.com/Buktal/dudu/issues/84)

## What to build

接通已有企业/组权限变化：查询和操作使用当前权限，范围变化通知客户端重新加载工作区，历史数据保持一份。

按已确认功能直接实现，字段与基本报文以最终数据契约为准。沿用现有组件、适配器、鉴权和数据库能力，不新增可靠投递、重放或并发协调框架。

## Acceptance criteria

- [ ] 账号换组只改现有组关系；新组可看原历史，无其他权限的原组员工不能读取、写入或接收通知，不复制访客或消息。
- [ ] 初始企业管理员、普通管理员、多组员工和跨企业边界沿用现有规则。
- [ ] 服务端在普通查询、保存、发送及 Socket 分发时检查当前权限；范围变化发送简单的重新加载通知。
- [ ] 客户端收到范围变化后重新查询身份和列表，移除已无权的对话、名片、固定会话和草稿，保留仍有权数据。
- [ ] 退出或切换员工销毁工作区及订阅；沿用无状态 JWT，不新增令牌撤销或权限快照历史。
- [ ] 使用现有管理能力/测试数据及两个真实 Desk 客户端验收迁组、增权、收权和身份切换，完成正常接口、界面及项目检查。
