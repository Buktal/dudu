## Parent

[DuduDesk 对接 Spec：共享接待、访客名片与消息同步 #84](https://github.com/Buktal/dudu/issues/84)

## What to build

让账号换组、员工退组或获得新组权限时，Desk 的查询、操作和 Socket 接收范围随当前权限变化。失去权限的访客从界面及缓存移除，新获权范围可重新加载，历史数据始终只有一份。

复用已有组与渠道账号能力、当前授权检查和客户端运行生命周期；不开发新的 Console 管理页面，不新增归属历史或令牌撤销体系。本票补齐动态变化的跨端行为，各业务票本身必须已经有静态权限校验。

## Acceptance criteria

- [ ] 账号由 A 组变到 B 组只更新当前授权关系，不复制、迁移或重新创建访客、名片和消息；B 组可查询原历史，A 组无其他权限者失去访问。
- [ ] 同时属于 B 组的员工及初始企业管理员保持合法访问；普通管理员不能凭角色获得全组权限，跨企业始终隔离。新获权范围重新初始化，不生成历史个人待办。
- [ ] 发生变化后，真实列表、历史、名片读写、状态操作、发送及受控媒体访问按最终授权时点校验；能力通知与订阅执行同一边界，服务端停止无权数据推送，不靠前端隐藏保障权限。
- [ ] 权限通知本身不携带无权敏感内容；客户端清理受影响列表、历史、名片、固定会话、回复/附件草稿和相关待处理提示，不干扰仍有权访问的访客。
- [ ] 正在查询、保存、准备附件、发送或处理 Socket 时权限失效，迟到结果不能使已清理访客重新出现，也不能写入其他目标；已经受理的发送结果按既定协议处理。
- [ ] 退出及身份替换对全部已接入资源生效：旧请求、订阅、能力和媒体准备结果不能写入下一员工工作区；沿用无状态 JWT，不把客户端清理描述为令牌立即撤销。
- [ ] 使用已有管理能力或隔离测试准备操作触发组变化，两个真实 Desk 客户端及真实 Server HTTP/Socket、独立 MySQL 验证动态收权/增权与各读写拒绝；不需要新管理页面才能验收。
- [ ] 复用适配器测试注入在途迟到结果，实际核验当前对话/并排/名片的清理；Desk 类型检查、lint、相关测试与 Server 编译、相关测试通过并更新实施记录。
