## Parent

[DuduDesk 对接 Spec：共享接待、访客名片与消息同步 #84](https://github.com/Buktal/dudu/issues/84)

## What to build

接通断线后的重新加载：Socket 重新连上后，重新调用已有初始化查询，显示后端最新数据。保留现有完整功能，不新增恢复协议

按已确认功能直接实现，字段与基本报文以最终数据契约为准。沿用现有组件、适配器、鉴权和数据库能力，不新增可靠投递、重放或并发协调框架

## Acceptance criteria

- [ ] 重连查询当前身份/权限、访客列表第一页，以及正在显示访客的名片和最近消息页
- [ ] 旧历史缓存失效后重新加载，不与新最近页强行拼接；更早消息仍通过向上分页读取，切换其他访客再按需加载
- [ ] 临时断线保留仍有权访客的文字和名片草稿；资料更新仍按现有覆盖提示处理。退出重登清空运行提示和缓存
- [ ] 消息结果、名片、接待状态直接取查询结果，已处理事项不重新提醒；沿用现有 ID/version 合并，不使用事件重放、差量对账、确认回执或专用恢复接口
- [ ] 两个真实 Desk 客户端连接真实 Server 和独立 MySQL，断开再连接后确认列表、当前对话、名片、权限及草稿正常；不要求提交窗口漏推、重复投递等专项故障演练
- [ ] 浏览器和打包桌面贯通全部已确认功能：登录、三模式、摘要/筛选/排序、分页/滚动、纯文本发送、消息展示、名片、结束/继续、权限和重连；完成项目检查及最终结构的迁移验证
