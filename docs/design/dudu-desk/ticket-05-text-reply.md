## What to build

接通纯文本回复：本地显示发送中，后端保存并发送，保存成功或失败结果，再向所有有权端通知一次

按已确认功能直接实现，字段与基本报文以最终数据契约为准。沿用现有组件、适配器、鉴权和数据库能力，不新增可靠投递、重放或并发协调框架

## Acceptance criteria

- [ ] 提交绑定当前访客与账号；实际发送员工由登录身份确定，HTTP 返回与通知沿用同一消息标识
- [ ] 本轮只启用纯文本发送，附件选择/文件粘贴/拖拽上传不进入真实发送流程；服务端校验当前权限及文本发送能力
- [ ] message 保存发送中、已发送、发送失败和失败原因。发送中不通知；成功或失败后，一次 Socket 携带完整消息及最新访客摘要
- [ ] 发起端更新本地气泡，其他端没有该消息时可新增；HTTP 返回的 delivery.failed 同样是已保存的消息，不能沿用旧逻辑判成无效响应。左侧与卡片更新摘要，未打开访客不预加载历史
- [ ] 成功回复按后端结果更新共享接待状态与已处理提醒；失败保持真实失败提示。已确认的新来信仍待回复，客户端不另算状态
- [ ] 重登查询后端记录，已受理消息及失败原因仍显示；本地未提交草稿不入库。保留失败气泡的手动重试，使用原访客/正文和新的 clientRequestId 调用同一发送接口，保留已入库的原失败记录。不新增未确认状态、发送核实接口、自动重试或重复投递专项处理
- [ ] 真实 Server、独立 MySQL、两个 Desk 客户端验收纯文本成功/失败、实际发送员工、三模式草稿和状态同步；完成项目检查并记录实际支持渠道
