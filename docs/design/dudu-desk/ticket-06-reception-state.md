## Parent

[DuduDesk 对接 Spec：共享接待、访客名片与消息同步 #84](https://github.com/Buktal/dudu/issues/84)

## What to build

让坐席结束或继续接待同一位访客，所有有权设备同步共享状态；已结束访客再次来信后沿用原会话并恢复待回复。

通过 visitor 的单一接待状态贯通操作、持久结果、通知及界面。继续接待的目标状态和结束与新来信的竞争顺序采用 #80/#83 最终契约，不增加结束布尔值或个人接待状态。

## Acceptance criteria

- [ ] 有权坐席的结束/继续操作保存并返回最新共享状态，非法动作和无权访客有约定反馈；不删除、复制或重新编号访客与消息。
- [ ] 未打开访客、当前完整对话和并排固定会话同步接待状态；队列成员、筛选、计数与对应已处理提醒一致更新。
- [ ] 已结束访客再次来信仍使用原访客/会话 ID，原有历史可读，并恢复待回复；不会因先前结束事件迟到而重新关闭新咨询。
- [ ] 手动结束与来信并发、重复状态操作、旧 HTTP 回应和 Socket 交错，均按最终业务顺序验收；客户端不能用事件到达顺序覆盖较新状态。
- [ ] 结束/继续不修改来访名片、未提交回复草稿或实际消息内容；未提交草稿仍受既有本地生命周期约束。
- [ ] 两个真实 Desk 客户端、真实 Server HTTP/Socket 与独立 MySQL 验证跨端操作、权限拒绝、再次来信和服务重启后的状态保留；InboxApi 控制延迟与重复响应。
- [ ] 实际核验各接待模式操作与状态菜单，Desk 类型检查、lint、相关测试与 Server 编译、相关测试通过，更新功能与实施记录。
