## Parent

[DuduDesk 对接 Spec：共享接待、访客名片与消息同步 #84](https://github.com/Buktal/dudu/issues/84)

## What to build

让坐席登录后按当前权限浏览、搜索、筛选和排序持久访客摘要，左侧列表与卡片读取同一份最后消息摘要，不预先下载全部对话。

随这条读取链路落地 visitor 与 message 所需结构及真实 InboxApi 查询；测试准备的访客与消息即可独立演示本票，渠道入站由后续票接入。不新增业务造数界面。字段、关联方式、排序口径和游标采用 #83 的最终契约。

## Acceptance criteria

- [ ] 通过新增 Flyway 迁移落地所需结构，保留现有六张基础表数据，不修改已提交迁移，不加外键。企业、接入账号和外部来访身份确定固定访客；同名跨账号不合并，内部访客 ID 同时作为会话 ID。
- [ ] 列表及单访客当前快照包含约定的身份、共享接待状态、最后消息摘要和新旧判断依据；一份持久数据供全部有权坐席查询，不新增个人状态或历史归属表。
- [ ] 搜索、来源/状态筛选、等待最久与消息最多排序，在完整授权范围内先计算再分页；状态计数不是当前页条数，消息总量不是已加载历史数量，并列及游标失效遵循最终契约。
- [ ] 条件切换会废弃旧条件请求；翻页按访客身份合并，空结果、尾页、失败与重试正确。名片更新不被当作新消息活动改变排序，搜索字段以定稿契约为准。
- [ ] 左侧列表与卡片共用摘要；卡片挂载不逐访客请求消息或资料。登录先获取摘要，只有实际展示完整对话的模式才启动对应最近页读取；核对原有默认选择首位访客的启动行为。
- [ ] 星标入口、筛选和接口保持移除；并排固定会话、来源/状态筛选与现有布局保留，不改写消息虚拟滚动。
- [ ] 真实 Server HTTP 与独立 MySQL 验证越权 ID、跨企业隔离、全量排序计数及游标边界；空库迁移和已有 V3 数据升级实际执行并确认 Admin 数据保留、重启可读。
- [ ] 在 InboxApi 边界验证条件切换的迟到响应和分页去重，实际核验列表、卡片及请求触发时机；Desk 类型检查、lint、相关测试与 Server 编译、相关测试通过，更新数据契约实施状态和功能记录。
