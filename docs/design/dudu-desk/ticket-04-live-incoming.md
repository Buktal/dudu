## Parent

[DuduDesk 对接 Spec：共享接待、访客名片与消息同步 #84](https://github.com/Buktal/dudu/issues/84)

## What to build

将约定渠道的文本来信接入真实 Server，并通过经过鉴权的 Socket 更新各设备的访客摘要、已打开对话和共享待回复状态。未打开访客也会显示新摘要，首次打开仍按需查询最近页。

本票建立本次登录的快照与订阅衔接，覆盖在线时的重复、乱序和查询竞态。跨资源长断线对账由恢复票完成；不能将本票完成描述为全部断线恢复已实现。沿用 #80、#82、#83 定稿结果，不自建通用事件平台。

## Acceptance criteria

- [ ] 通过约定的真实渠道入站边界处理文本，按来源身份创建或复用 visitor，并将消息和对应摘要/共享待回复状态一致地持久化；重复来源消息不重复建访客、消息或累计计数。同键不同内容按定稿契约处理。
- [ ] 入站认证与来源账号匹配沿用最终渠道契约，失败事务不发出有效通知；通知不会暴露未提交内容。需要补偿的提交后漏推可被最终恢复协议识别，不以“提交后发一次”宣称可靠送达。
- [ ] Socket 订阅使用真实员工身份和当前企业/组权限，只向有权设备分发；服务端身份与版本用于合并，不依赖客户端时钟或事件到达顺序。
- [ ] 初始化快照与订阅按定稿协议衔接；在开始查询、订阅就绪和查询返回之间注入来信，最终摘要与消息均不遗漏、不倒退。
- [ ] 未打开访客连续来信只更新必要摘要及本次运行提示，不启动历史预取；首次打开仍读取最近页。已打开对话同步合并来信，列表/卡片、筛选成员、排序和计数按查询契约更新。
- [ ] 接待状态只有服务端共享的一份；旧 markRead 流程不再持久化个人阅读，不因打开对话改变待回复状态。本次运行提示服从共享状态，首次加载历史不生成个人待办。
- [ ] 退出或身份替换取消订阅，迟到通知不得写入下一员工工作区；重复/乱序通知不重复插入消息或增加提示，不用不完整资源的总版本丢弃其他资源更新。
- [ ] 两个真实 Desk 客户端连接真实 HTTP/Socket 与独立 MySQL，验证同一来信同步、未打开访客与初始化竞态；渠道侧可用受控替身，待验收的 Server 与客户端通信不得 Mock。
- [ ] 复用 InboxApi 测试控制重复、乱序及延迟，检查真实持久结果；Desk 类型检查、lint、相关测试与 Server 编译、相关测试通过，记录渠道支持范围与恢复尚未覆盖的边界。
