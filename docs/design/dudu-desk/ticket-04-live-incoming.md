## Parent

[DuduDesk 对接 Spec：共享接待、访客名片与消息同步 #84](https://github.com/Buktal/dudu/issues/84)

## What to build

将真实访客来信接入消息表，更新共享访客摘要，通过 Socket 通知所有有权端。登录连接 Socket 后加载初始数据

按已确认功能直接实现，字段与基本报文以最终数据契约为准。沿用现有组件、适配器、鉴权和数据库能力，不新增可靠投递、重放或并发协调框架

## Acceptance criteria

- [ ] 按企业、渠道账号和外部身份创建或复用 visitor；消息及本次访客状态/最后消息在数据库保存后，直接推送完整消息和访客摘要
- [ ] 首次来信包含足够的访客信息，未见过该访客的客户端也能新增条目；未点开只更新摘要，点开仍取最近一页
- [ ] 当前完整对话接收消息，列表与卡片同步摘要、状态和计数；影响筛选/排序时重新读取列表第一页
- [ ] Socket 使用现有员工身份及企业/组权限；退出销毁订阅。接待状态共享，不持久化个人阅读，初始历史不产生个人待办
- [ ] 通过真实 Server HTTP/Socket、独立 MySQL 和两个 Desk 客户端验收新访客、已有访客及未打开访客的正常来信流程
- [ ] 核验实际界面，Desk 类型检查/lint/相关测试及 Server 编译/相关测试通过；保留原滚动，不新增事件表、重放和投递确认
