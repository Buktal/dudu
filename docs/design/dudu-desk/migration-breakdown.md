# DuduDesk 生产迁移拆票方案

来源[规格 #50](https://github.com/Buktal/dudu/issues/50)，2026-09-15 发布，实施票 #51–#59 已全部交付。下列数字是方案序号，实际 Issue 链接见各票

## 拆分原则

每张票都沿用户操作贯穿前端契约、业务状态、界面和相关测试，并可独立演示。真实 Server 与渠道收发不在本阶段；需要外部能力的流程以统一契约和开发适配器验收，正式运行准确表达不可用

现有正式 Desk 尚无会话业务，必要的主题控制整理放在票 1，读取契约和公共状态随票 2 的阅读流程建立。每张票自带相应检查，票 9 负责窗口和应用生命周期的整合行为。沿用已收尾原型，不重复探索设计

## 建议的九张票

1. **工作台入口与十二主题**
   **前置依赖：**无，可立即开始
   **交付：**在正式 Desk 打开工作台，连续比较十二主题，重开后恢复偏好；建立三种模式共用的入口和样式控制
   **GitHub：**[#51](https://github.com/Buktal/dudu/issues/51)

2. **自在模式查看会话与历史**
   **前置依赖：**草稿票 1
   **交付：**在自在模式选择来访用户、查看文本历史和基本资料；支持分页、长列表以及加载和服务未连接状态
   **GitHub：**[#52](https://github.com/Buktal/dudu/issues/52)

3. **文字回复、独立草稿与连续接待**
   **前置依赖：**草稿票 2
   **交付：**给准确的会话发送文字，保留独立草稿，处理失败与重试，并区分普通发送、发送并下一位和结束接待
   **GitHub：**[#53](https://github.com/Buktal/dudu/issues/53)

4. **来信、回执与连接状态更新**
   **前置依赖：**草稿票 3
   **交付：**来信和回执能更新现有会话，重复或乱序事件不污染状态；连接中断时保留正在输入的内容
   **GitHub：**[#54](https://github.com/Buktal/dudu/issues/54)

5. **会话筛选、星标与来访资料维护**
   **前置依赖：**草稿票 2
   **交付：**搜索和筛选会话，查看准确的来源资料，并可靠地保存星标、标签和接待备注
   **GitHub：**[#55](https://github.com/Buktal/dudu/issues/55)

6. **并肩双窗接待**
   **前置依赖：**草稿票 3
   **交付：**手动固定第二段会话，在两窗间切换回复，保留草稿；并肩模式与自在共享数据和偏好
   **GitHub：**[#56](https://github.com/Buktal/dudu/issues/56)

7. **速答卡片与完整对话**
   **前置依赖：**草稿票 4
   **交付：**从最新消息卡直接回复，随时打开完整历史；新来信原位更新，卡片和完整对话共享草稿
   **GitHub：**[#57](https://github.com/Buktal/dudu/issues/57)

8. **附件回复与媒体消息**
   **前置依赖：**草稿票 3
   **交付：**按会话能力选择和发送附件，保留附件草稿与重试目标；正确呈现媒体和渠道卡片
   **GitHub：**[#58](https://github.com/Buktal/dudu/issues/58)

9. **窗口变化、重开恢复与桌面交付**
   **前置依赖：**草稿票 5、6、7、8
   **交付：**窗口变窄、切换模式和重新打开 Desk 时保持正确状态，完成整套工作台在 Web 与 Tauri 中的交付验收
   **GitHub：**[#59](https://github.com/Buktal/dudu/issues/59)

## 依赖依据

- 票 2 需要票 1 的正式工作台、统一样式和偏好边界
- 票 3 和票 5 都直接使用票 2 的会话标识、查询、状态和 API 边界；资料维护无需等待回复功能
- 票 4 需要票 3 的发送关联标识和受理/失败/未知状态，才能合并后续回执
- 票 6 和票 8 直接复用票 3 的受控编辑器、草稿与发送命令，彼此没有阻塞关系
- 票 7 需要票 4 的来信更新与去重，才能验收稳定更新的速答卡；它不依赖并肩布局
- 票 9 直接依赖票 5、6、7、8；前面的共同基础已通过这些依赖覆盖，避免重复添加间接依赖

每个实现任务应从父规格核对完整约束；各票已引用规格 #50、标记 ready-for-agent，并建立上述 GitHub 原生阻塞关系。父规格的标题、正文、状态和标签保持原样
