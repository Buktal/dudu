[DuduDesk 对接 Spec：共享接待、访客名片与消息同步 #84](https://github.com/Buktal/dudu/issues/84)

## What to build

接通现有全部消息展示类型，左侧和卡片共用摘要。媒体先保存渠道已有链接或标识，复用渠道读取方式；本轮仍只发送纯文本。

按已确认功能直接实现，字段与基本报文以最终数据契约为准。沿用现有组件、适配器、鉴权和数据库能力，不新增可靠投递、重放或并发协调框架。

## Acceptance criteria

- [ ] 文本、图片、文件、音视频、链接、位置、引用、卡片、系统及未知内容按实际渠道字段映射现有组件，不删减已认可的展示功能。
- [ ] 所有消息共用 message；content 保存所需结构化字段和媒体引用，不按类型建表，不保存整个无关渠道载荷。
- [ ] 历史、实时与重登查询的展示一致；卡片只取最后摘要，完整对话按需加载。
- [ ] 媒体通过渠道链接或现有读取能力打开，缺失/失效沿用现有提示；访问沿用渠道与企业权限，不预建永久副本、素材清理或通用文件平台。
- [ ] 在浏览器和打包桌面核验各消息展示、媒体打开/失败反馈与滚动；保持原虚拟列表。
- [ ] 真实 Server、独立 MySQL 与受控渠道样本验证读取和持久化，完成项目检查，记录实际支持字段与渠道读取限制。
