## Decision

2026-10-10，按用户要求保留功能并收简实现；本票规则已确定，精确字段和报文见[最终对接契约](https://github.com/Buktal/dudu/issues/83)。

- message 保存发送中、已发送、发送失败及原因；不另建状态、请求或回执表。
- 发起端立即显示发送中，后端入库并直接调用渠道。成功/失败后保存结果，通知一次完整消息和最新访客摘要；发送中不通知。HTTP 返回该条持久消息。
- 每条回复记录真实员工；访客接待状态与消息发送状态分开。结束、继续及再次来信由后端保存并通知。
- 复用现有消息 ID/clientRequestId/version 完成普通界面合并；失败气泡的手动重试使用新的 clientRequestId 调用原发送接口，保留已入库失败记录。不增加结果未确认、发送核实、自动重试或重复投递专项协议。
- 本轮纯文本；已受理记录重登按库展示；消息字段、最后摘要和会话内 sequence 由普通三表读写维护。

此前额外可靠投递建议已撤回，不再是开工门槛。关闭表示消息设计完成，不表示渠道收发已经实现。
