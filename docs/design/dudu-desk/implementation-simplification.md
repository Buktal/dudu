# DuduDesk 实现方式完整收简（2026-10-10）

用户要求重新审查之前全部决策：**保留已经认可的功能，把实现改为简单、直接的一条线；先接通全部核心功能，不为尚未发生的问题设计额外协议。**本次不是功能删减或重新征询产品需求。

## 逐项核对

| 原有功能 / 决定 | 本轮直接实现 |
| --- | --- |
| 企业登录、员工、多组、初始管理员 | 复用现有六表与 JWT，沿用已完成的认证子契约，不新增会话/撤销表 |
| 一份访客、一份名片、一套消息 | visitor / visitor_profile / message 三表，访客 ID 共用为会话 ID |
| 来源账号与访问范围 | 查询现有账号所属组；不复制历史、所有权或权限快照 |
| 列表、搜索、排序、计数 | 数据库普通查询和分页；更新影响排序时重取第一页，不做排名快照或游标修复 |
| 卡片与三种接待方式 | 卡片只显示最后摘要；完整对话最近页＋向上加载，复用当前缓存/组件 |
| 访客来信、多端共享状态 | 保存消息及访客摘要后直接通知；陌生访客带完整信息入列 |
| 纯文本回复 | 保存发送中→直接发送→保存成功/失败→通知一次；不广播发送中。现有手动重试通过同一发送接口发一条新消息，保留已入库失败记录 |
| 发送结果与重登 | message 保存三态；重登查询显示。撤回新增的未确认状态、结果核实、自动重试及重复投递专项方案 |
| 结束、继续、再次来信 | 后端普通状态更新并通知；继续沿用现有待回复，不做前端并发裁决 |
| 共享名片、标签、备注 | 直接读取/保存并通知；编辑时收到更新则保存前提示一次覆盖，确认后普通保存 |
| 全部已有消息类型与媒体打开 | 原组件展示，保存渠道已有字段/链接/标识，按需读取；不建永久副本或通用文件平台 |
| 动态权限与退出 | 后端沿用当前权限校验；范围通知后重查工作区，无权数据移除 |
| 临时断线与重新登录 | 重新调用初始化查询，消息缓存从最近页开始，历史向上取；临时断线保留合法草稿 |
| 草稿、固定会话、表情/快捷回复、主题/设置、原滚动 | 保留已认可的前端行为；没有同步要求的本地/静态能力不新增服务端表 |
| 之前明确的范围变更 | 星标已移除、卡片只显示摘要、附件发送延期继续有效，其余功能保持 |

## 撤回的额外实现要求

不新增未确认结果状态、发送核实/自动重试接口、独立幂等或序号服务、事件表、投递确认、持久恢复游标、事件重放、增量对账、后台补偿、排名冻结、资料冲突协商和自有文件存储平台。已有 ID/version 合并与普通事务继续复用，不借收简重写前端。

不把这些方案或专项故障演练作为开工门槛。保留普通接口、持久化、企业权限、两个真实客户端和打包桌面的功能验收；真实问题出现后就地修复。

## 定稿与实施

字段、类型、索引、路径、参数、响应和四类 Socket 报文已经写入[最小对接契约](implementation-contract.md)，作为单一事实源。消息、媒体、查询恢复的规则已确定，最终契约不再等待这三项的复杂方案。

实施按一条线：企业登录 → 访客列表 → 对话历史 → 来信 → 文本回复 → 结束/继续 → 名片 → 消息媒体展示 → 权限变化 → 重连初始化。各票做完自身功能再进入下一票；附件发送保持延期。

本次交付设计和实施依据，尚未执行数据库迁移或接通后端业务，不能把设计票关闭算作实施票完成。
