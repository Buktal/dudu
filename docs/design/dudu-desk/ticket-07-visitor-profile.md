## Parent

[DuduDesk 对接 Spec：共享接待、访客名片与消息同步 #84](https://github.com/Buktal/dudu/issues/84)

## What to build

让有权坐席查看并共同维护来访名片。别人保存后，查看中的右侧面板刷新；编辑中的坐席保留草稿，在保存前可确认覆盖，取消则看到最新服务端资料。

随完整名片读写链路落地 visitor_profile，以访客 ID 作为一对一主键/关联值；字段与覆盖协议以 #82/#83 最终契约为准。沿用现有资料编辑边界，不新增备注历史或标签字典。

## Acceptance criteria

- [ ] 新增版本化迁移，visitor_profile 仅保存约定的渠道扩展资料、共享标签和备注；名称/头像共用 visitor，不重复存储，不增加独立名片 ID 或外键。
- [ ] 获取及保存名片执行当前企业与账号权限；未提供、空内容、有效值保持区别，复制渠道资料不夹带内部标签/备注。
- [ ] 有权客户端通过 Socket 收到名片更新，未编辑面板及时刷新；未打开名片可更新或失效缓存，不为每次通知无条件拉取全部对话。
- [ ] 远端更新保留本地编辑输入。保存时如基线已变化，按最终协议提示并允许确认覆盖；漏收通知及确认后又有他人保存的竞争同样处理，不退回静默覆盖或永久拒绝保存。
- [ ] 覆盖仅限本次表单可编辑的标签和备注，不用旧整个访客对象覆盖身份、渠道资料、最新消息或接待状态。
- [ ] 撤销编辑显示最新服务端快照；保存后继续输入的新草稿不被较早保存回应清空。旧详情、旧保存回应与重复推送均不回退已知较新资料。
- [ ] 名片更新不改变消息活动排序；若变更影响当前搜索命中，按查询契约更新列表及计数，不能仅更新右侧面板。
- [ ] 两个真实 Desk 客户端与真实 Server HTTP/Socket、独立 MySQL 验证查看/编辑、覆盖确认、漏推后保存、再次并发及权限拒绝；InboxApi 边界控制保存期间继续输入和迟到响应。
- [ ] 实际执行空库及已有版本升级，确认既有消息/Admin 数据保留且重启后名片仍在；核验实际编辑界面，Desk 类型检查、lint、相关测试与 Server 编译、相关测试通过并记录结果。
