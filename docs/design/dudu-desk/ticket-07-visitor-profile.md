[DuduDesk 对接 Spec：共享接待、访客名片与消息同步 #84](https://github.com/Buktal/dudu/issues/84)

## What to build

接通共享名片读取和普通保存。别人更新时查看界面刷新，编辑输入保留，收到更新后在保存前提示一次是否覆盖。

按已确认功能直接实现，字段与基本报文以最终数据契约为准。沿用现有组件、适配器、鉴权和数据库能力，不新增可靠投递、重放或并发协调框架。

## Acceptance criteria

- [ ] visitor_profile 使用访客 ID 一对一保存渠道资料、共享标签和备注；名称/头像复用 visitor，不另建名片 ID、标签字典或备注历史。
- [ ] 读取和保存校验现有权限；保存仅接受标签/备注，复制渠道资料不夹带内部备注，保留缺失与空内容的区别。
- [ ] 保存后直接推送最新名片；未编辑面板刷新，编辑中的输入保留，并标记已收到更新。
- [ ] 编辑期间收到更新时，保存前提示一次；确认后正常保存，后保存覆盖。取消编辑显示最新资料，不设计版本冲突拒绝、漏通知补偿或反复确认。
- [ ] 名片保存不更新消息活动时间；涉及当前搜索时重新查询列表。保存期间使用普通提交状态，保存的内容与用户提交一致。
- [ ] 两个真实 Desk 客户端、真实 Server 和独立 MySQL 验收读取、保存、通知、覆盖提示和取消；检查迁移/重登保留、实际界面及项目已有检查。
