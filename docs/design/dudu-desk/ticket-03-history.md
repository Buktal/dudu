## Parent

[DuduDesk 对接 Spec：共享接待、访客名片与消息同步 #84](https://github.com/Buktal/dudu/issues/84)

## What to build

让坐席在专注、并排或卡片展开的完整对话中，首次读取最近一页消息，向上滚动再读取更早历史。三种接待方式共享同一访客缓存、回复草稿与附件草稿。

复用现有 InboxApi 和历史合并边界，使用 #83 定稿的稳定消息身份与分页契约；本票可用持久文本消息独立验收。媒体类型展示由后续票补齐。

## Acceptance criteria

- [ ] 真实历史查询在当前企业及账号权限内返回有界最近页或更早页，明确消息顺序、更早游标和是否还有历史；不存在一次读取整个对话的默认路径。
- [ ] 首次展示完整对话时查询最近页，向上滚动才取更早页；同页在途请求合并，空历史、尾页和查询失败可以正确展示或重试。
- [ ] 历史初始化成功与缓存内消息数量分开记录；已有临时消息或推送消息不表示初始化完成。切回有效缓存无需重查全部历史，失效后按契约重新读取。
- [ ] 页面与实时结果按稳定消息身份合并，重复消息只有一条；旧请求不移除较新消息或倒退已知结果。更早游标来自历史页面，不被最新消息替代，也不用作 Socket 恢复位置。
- [ ] 三种接待模式及完整对话共用历史、回复草稿和附件草稿；并排固定会话保持可用，切换焦点不混淆访客。
- [ ] 在原有虚拟滚动写法下，向前补页保持阅读位置；翻阅历史时加入新消息不覆盖旧页或强制跳到底部，卡片仍只读取最后摘要。
- [ ] 真实 Server HTTP 与独立 MySQL 验证多页边界、同序并列、访问隔离；InboxApi 边界模拟推送先到、旧页后到及重复页面，断言最终消息和更早游标正确。
- [ ] 浏览器和打包桌面实际核验三种模式、完整对话、向上分页、草稿、并排固定及滚轮阅读；Desk 类型检查、lint、相关测试与 Server 编译、相关测试通过并记录证据。
