## What to build

**本轮延期（2026-10-10）**：用户明确“发送消息时先不做附件，就先纯文本”。本票移出当前实施范围，以 not planned 关闭，不作为任何本轮票据的阻塞，不表示已实现。以下保留原范围供将来重新评估；本轮纯文本入口限制由文本回复票完成，收到的非文本消息展示仍在原展示票中

让坐席按当前渠道能力准备并发送附件，保留本地草稿，看到真实准备/发送结果；其他有权设备及重登后的历史能够按约定展示已发送内容

复用文本发送的目标绑定、逻辑请求、结果核实和共享状态规则，以及已完成的媒体展示/访问能力。附件归属、大小和类型限制、清理与生命周期以 #81/#83 为准，不建立通用文件平台

## Acceptance criteria

- [ ] 当前回复能力决定可选附件类型及限制；客户端有明确反馈，准备和最终发送仍由服务端校验访客、账号权限及渠道能力，拒绝不属于合法目标的媒体引用
- [ ] 附件准备成功返回可发送引用，失败保留可操作的失败状态，不伪造可发送素材；取消或准备后未发送的素材按最终契约清理，不能误删已发送消息所需资源
- [ ] 准备期间切换访客、模式或并排焦点不改变原发送目标，不把素材写入别人的草稿；三种模式和完整对话复用该访客已有附件草稿
- [ ] 准备后、发送前能力发生变化时，编辑器收到约定的更新并提示；最终发送再次校验，失效能力通知或迟到准备响应不能绕过限制
- [ ] 附件发送沿用同一消息与 clientRequestId，HTTP/Socket 交错只有一个逻辑气泡；超时先核实，重复提交不会重复投递。真实失败原因、发送员工与共享状态规则同文本发送
- [ ] 已发送内容在另一设备和重新登录后按媒体契约可访问；本次运行的临时失败摘要不冒充后端真值，不新增个人阅读状态或跨设备草稿同步
- [ ] 真实 Server HTTP/Socket、独立 MySQL、可控渠道与媒体存储验证准备失败、取消清理、限制变化、重复提交、权限拒绝及重登访问；两个 Desk 客户端核验显示一致
- [ ] 实际核验附件草稿与失败交互，Desk 类型检查、lint、相关测试及 Server 编译、相关测试通过；若有持久结构调整，新增迁移并实测升级，记录支持范围
