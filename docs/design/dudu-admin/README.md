# DuduAdmin 功能规划与设计交接

状态：首版功能范围已确认，交互细节待细化。记录功能与设计交接，不代表界面或后端已经实现。

正式 Spec：[DuduAdmin 首版前端与数据契约 Spec](https://github.com/Buktal/dudu/issues/68)。GitHub Issue 是完整规格的维护入口，包含用户故事、实现约束和已确认的分阶段测试边界；本文件保留功能摘要与交接索引。Spec 仍依赖数据契约及其前置业务决策定稿，发布不代表所有细节已确认。

[前端实施票索引](ticket-breakdown.md)：经用户确认已发布 9 张票，包含各票交付内容、验收条件和原生阻塞关系。先完成数据契约前置，再从登录、环境选择与管理入口开始实施。

## 本次目标与分工

本次会话只梳理功能、记录决策与想法。用户将在新的会话中专门进行前端视觉设计和开发；本次不确定页面布局、品牌继承方案、组件外观或首页。

交付顺序更新为：**功能规则确认 → 表结构与接口字段对齐 → 独立设计会话完成 Admin 前端 → 后端实现与真实接口联调**。[企业开通草案](company-onboarding.md) 保留真实业务闭环要求，后端实施安排在前端之后；字段与接口契约设计提前，避免前后端重复命名和转换。

2026-09-30 最新要求：交付的是完成后直接对接接口的正式 Admin 前端，完全不使用模拟数据或模拟登录。接口未就绪时显示真实的服务不可用或请求失败，不用示例数据替代。开发环境提供服务地址选择，生产构建隐藏入口并固定线上地址。

## 已确认决定

| 事项 | 决定 |
| --- | --- |
| 使用者 | DUDU 运营方；首版只有用户本人，一个平台管理员账号 |
| 产品分工 | Admin 管理平台运营；Console 管理企业内部员工、接待组和渠道接入账号；Desk 用于接待 |
| 完整程度 | 企业开通与基本维护，加上运营概览、操作记录、个人账号，形成完整的企业运营后台 |
| 登录 | 有独立登录界面；开发时可预填 `Admin / Admin`，但始终请求真实认证，不据此在前端判定成功；生产不预填开发凭据 |
| 数据 | 不使用模拟数据；表结构与接口字段先对齐，前端按契约开发，结果来自真实服务 |
| 服务环境 | 开发可查看、切换本地与线上地址；生产固定线上地址，忽略开发时保存的选择；见 [接口环境设计](api-environments.md) |
| 企业资源查看 | 只看各企业员工、接待组、渠道接入账号的数量与状态汇总；日常管理仍由 Console 负责 |
| 商业管理 | 首版不做套餐、收费及配额，先完成企业运营功能 |
| 视觉设计 | 尚未选择；交由用户另开的前端设计会话决定 |
| 当前会话产物 | 功能、决策、待定事项文档及正式 Spec；不实施前端、后端、业务表或真实登录 |

`Admin / Admin` 是当前前端开发约定，不等于已确定生产凭据和真实账号初始化方式。企业内部管理员凭据的已确认部分与待定流程见下方决策票。

## 已确认的功能清单

下表定义功能与用户要完成的操作，不将功能分组直接等同于侧边菜单或页面数量。搜索字段、表单字段和状态表达为细化建议，待后续讨论及设计会话展开。

| 功能 | 用户需要完成的操作 | 前端需要覆盖的结果 |
| --- | --- | --- |
| 平台登录与退出 | 请求真实认证，退出后回到登录入口 | 正常进入、输入错误、服务不可用、退出后的状态 |
| 开发环境选择 | 登录前后均可查看目标服务，开发时可选择本地或线上并修改本地 IP | 切换后清理旧连接状态并重新登录；生产入口隐藏且只使用线上地址 |
| 企业列表 | 找到已开通企业并进入详情 | 有数据、无数据、搜索无结果；建议支持名称／编号搜索、状态筛选与分页 |
| 创建企业 | 随机生成或手输六位企业 ID 并检测可用性，填写企业资料与初始管理员信息 | 检测中、可用、占用、检测失败；提交成功、失败及并发 ID 冲突；成功后可在列表和详情找到企业 |
| 企业详情 | 查看企业身份、基础资料、当前状态及管理员非敏感资料 | 创建后的结果、修改后的结果、停用状态；基础资料范围已确认，规则见下方决策票 |
| 编辑企业资料 | 修改企业的基本资料 | 校验、保存、取消；列表和详情同步显示修改结果 |
| 停用与恢复企业 | 暂停企业使用并在需要时恢复 | 确认操作、原因与影响说明、结果反馈；真实权限失效范围留待后端阶段确定 |
| 重置企业管理员密码 | 为指定企业的管理员重新设置登录凭据 | 明确目标企业和管理员，确认重置，展示操作结果；具体凭据交付方式待定 |
| 运营概览 | 了解企业总量、启用／停用数量和近期开通情况 | 与企业数据一致；统计口径及是否作为首页留待细化 |
| 企业资源汇总 | 查看各企业员工、接待组、渠道接入账号数量及状态概况 | 只读汇总；不提供资源明细或企业内部编辑功能 |
| 操作记录 | 回查企业创建、编辑、停用、恢复和密码重置等操作 | 展示时间、对象、操作与结果；支持必要的查询，避免记录密码内容 |
| 个人账号 | 查看当前平台账号，修改自己的密码 | 当前账号信息、改密表单与成功／失败反馈；改密后的登录行为待细化 |

创建企业与初始管理员必须共同成功或共同失败；前端按这个完整操作表达接口结果，真实数据库提交在后端阶段实现与验证。

企业 ID 不再自增。创建页提供“随机生成”和“检测”：随机生成由后端生成并查重，手输后可单独检测；两种方式均限制为 `100000–999999`。检测不占号，最终创建仍由数据库主键约束防重；详细交互与接口候选见 [企业 ID 选择与检测](data-contract.md#创建前的企业-id-选择与检测)。创建成功后 ID 不可修改。

## 首版范围之外

“全面”指本次已确认的企业运营功能，不扩展为完整商业收费平台或企业内部控制台。

- 套餐、计费、商业到期限制、员工／渠道配额、订单、支付、退款和发票。
- 多个平台运营账号的管理及平台角色权限配置。
- 企业内部员工、接待组和渠道接入账号的明细管理；这些由 Console 承接。
- 访客聊天内容查看、代坐席接待和真实渠道收发。

## 正式前端的交互与对接要求

- 登录后能完成已确认的主要操作，不能只展示静态页面或无效果按钮。
- 创建、修改、停用／恢复等真实接口结果在相关视图中一致；接口未实现的功能不能假装成功。
- 覆盖校验失败、提交中、操作成功和失败等必要状态；重置密码与停用企业需要清楚展示操作对象。
- 页面数据和操作按先行确认的接口契约组织；不添加运行时模拟数据、模拟适配器、演示数据管理或重置功能。
- 平台管理员和企业管理员始终使用不同的语义与权限范围；已有 [企业隔离决策](../../adr/0011-enterprise-group-access.md) 继续适用。

## 后续设计会话的交接说明

先阅读本文件及 [正式 Spec](https://github.com/Buktal/dudu/issues/68)，核对“已确认功能”“范围之外”和“需细化事项”，再结合实际前端骨架设计。当前 `dudu-admin` 已有 React、Vite、Tailwind 与 shadcn 基础，真实实现以 [项目 README](../../../dudu-admin/README.md) 和代码为准。

设计会话负责视觉与交互方案、前端实施及实际界面验收。当前会话负责功能决策与先行数据契约；涉及新增模块或业务范围变化时继续确认。完成前端后，按确认的契约及最终操作行为，继续 [Server 总体设计](../dudu-server/README.md) 中的后端实施与联调。
