# DuduAdmin 接口环境设计

状态：2026-10-08 简化为双通道模型。原运行时环境切换（登录页/顶栏 EnvironmentMenu、本地地址编辑）已随用户确认移除，历史决策见 [开发与生产环境如何选择并连接真实接口？](https://github.com/Buktal/dudu/issues/66)；本文件记录现行连接方式

## 数据与连接原则

- 正式前端直接面向真实接口，不使用模拟企业、统计数据、模拟登录成功或本地业务数据仓库
- 接口不可用时显示连接失败或服务不可用，允许重试；不能把请求失败显示成空列表、零统计或操作成功
- `Admin / Admin` 只保留为先前要求的开发登录表单预填值，请求仍交给真实认证接口。生产不预填开发凭据
- 占位域名尚不可用，不表示存在已部署后端

## 现行连接模型

| 通道 | 地址 | 说明 |
| --- | --- | --- |
| 开发 | 同源 `/api`（origin 为空串） | `vite.config.ts` 的 `server.proxy` 将 `/api` 转发到 `http://127.0.0.1:8080`；浏览器请求同源，无跨域 |
| 生产 | `VITE_API_ORIGIN` 构建注入 | 默认占位 `https://api.dudu.example`，部署时替换真实域名；`client.ts` 校验其为 HTTP/HTTPS 源地址 |

- 请求层（`api/client.ts`）按 `import.meta.env.DEV` 选择通道：开发恒为同源代理，不读取任何浏览器本地存储的地址
- 会话凭据（`dudu-admin.session`）按 origin 绑定，通道固定的前提下仅用于同地址恢复
- 生产跨域由部署层解决：同源反向代理，或网关（如 Nginx）添加 CORS 头；服务端不注册任何 CORS 处理（`DevCorsConfig` 已移除）

## 移除记录

- 运行时切换本地/线上环境与编辑局域网地址的入口（EnvironmentMenu）、`api/environment.ts` 已删除；如需指向其他后端，改 `vite.config.ts` 代理目标后重启开发服务器
- 2026-10-08 用户确认：跨域交给代理/网关层，不在代码里做；由此服务端 CORS 与前端切换器一并退场
