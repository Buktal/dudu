# DuduAdmin 接口环境设计

状态：功能与行为已明确，尚未实现环境选择界面或 HTTP 请求模块。决策记录见 [开发与生产环境如何选择并连接真实接口？](https://github.com/Buktal/dudu/issues/66)。

## 数据与连接原则

- 正式前端直接面向真实接口，不使用模拟企业、统计数据、模拟登录成功或本地业务数据仓库。
- 接口不可用时显示连接失败或服务不可用，允许重试；不能把请求失败显示成空列表、零统计或操作成功。
- `Admin / Admin` 只保留为先前要求的开发登录表单预填值，请求仍交给真实认证接口。生产不预填开发凭据。
- 本地环境与线上环境都指向真实 HTTP 服务；占位域名尚不可用，不表示存在已部署后端。

## 入口与地址

| 项目 | 设计 |
| --- | --- |
| 登录前入口 | 登录页右上角的“环境”入口；未登录也能调整服务地址 |
| 登录后入口 | 顶部显示当前开发连接环境，同一入口可查看、切换 |
| 本地环境 | 默认 `http://127.0.0.1:8080`；允许填写开发机的局域网 IP 与端口 |
| 线上环境 | 暂用保留示例域名 `https://api.dudu.example`；部署时替换为真实域名 |
| 地址格式 | 配置的是服务源地址（协议、主机、端口），不包含 `/api`；请求层统一添加已有 `/api` 前缀 |
| 本地选择保留 | 开发模式可在当前浏览器记住环境与本地地址；只保存连接设置，不保存业务记录 |

`127.0.0.1` 适用于浏览器和 Server 在同一台机器。使用其他设备访问时填写 Server 所在开发机 IP。8080 来自当前无 `server.port` 覆盖时的 Spring Boot 默认值，不表示已验证运行中的服务。

环境入口的位置是本轮的常规交互设计建议，最终组件外观沿用后续视觉设计。

## 开发与生产边界

- 环境选择与本地地址编辑仅在 Vite 开发模式启用。前端实现同时约束入口和地址解析，不能只隐藏按钮。
- 生产构建固定使用发布配置中的线上地址；忽略浏览器中保存的开发环境选择、本地地址和 URL 中的覆盖参数。
- 不根据浏览器当前 IP 推断是否为生产，也不把运行时可改的开关当作生产限制。
- 生产域名从构建配置注入，接口域名不是密钥；配置项具体名称在前端实现时沿用项目环境配置。
- 开发模式切换地址后，取消旧环境的请求、清除旧环境身份与页面缓存并返回登录页。迟到响应不能写入新环境，旧令牌不能发给新地址。
- 地址输入只接受 HTTP/HTTPS 源地址，去掉末尾斜杠；不把账号、密码或令牌放入地址。

## 后端接入要求

当前 Server 无业务登录接口，也尚未配置浏览器跨域；Admin 的 Vite 配置中也没有代理。开发浏览器直连本地 IP 的不同端口时，后端需允许实际开发页面来源及所用方法、请求头，并处理预检；不能依靠浏览器禁用安全检查。

生产按最终部署决定同源反向代理或明确的跨域来源配置。环境选择只改变连接目标，不授予任何权限；统一响应、认证与授权继续由 Server 承担。

## 验收要求

1. 开发登录页和登录后界面均能查看当前目标；修改本地 IP 后，请求确实发往该地址。
2. 接口不可达时出现可重试的真实失败状态，没有示例记录、虚构统计或假登录成功。
3. 切换环境不会带走旧令牌或混入旧响应；重新登录后再加载新环境数据。
4. 生产包不显示环境入口；即使预先保存了开发地址，生产请求仍只使用发布配置的线上地址。
5. 当前占位域名不可用是预期状态；部署后替换配置，再完成真实接口联调。
