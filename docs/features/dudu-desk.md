# DuduDesk 功能图谱

记录当前前端工作台的功能、入口与限制。子项目概览见 [DuduDesk README](../../dudu-desk/README.md)，当前接口边界见 [InboxApi](../../dudu-desk/src/features/inbox/api.ts)，后端对接实施依据见已定稿的[最小契约](../design/dudu-desk/implementation-contract.md)；企业登录、访客摘要列表、按需对话历史、实时来信订阅与纯文本回复已接通，名片与结束／继续等业务尚待逐项接通。

## 功能与入口

2026-10-12 纯文本回复接通：真实适配器已接发送接口（`POST /api/desk/visitors/{visitorId}/messages`）与回复能力（会话对象与 `GET …/capability` 同源），发送中本地先显示气泡，HTTP 返回与 Socket 通知按同一消息 ID 合并为一条，渠道失败也按已保存的失败气泡展示真实原因并保留手动重试；附件准备/上传/发送延期，已收到的非文本内容继续展示，真实适配器下选择/粘贴/拖拽入口按能力停用（不伪装可用），Mock 场景按自身能力数据保持可用。

| 会话队列 | “我的会话”旁图标打开查询浮层，包含搜索、状态、来源和排序；三行紧凑列表保留原信息 | 已接入真实 Server：登录后按当前授权范围读取摘要列表，搜索/状态/来源筛选与排序在服务端执行并普通分页，计数为全部授权范围；条件切换废弃旧条件在途响应，翻页按访客身份合并去重；有筛选条件时图标显示圆点，清空后移除；Ctrl+K 打开搜索；三种模式共用；星标功能已移除 |

| 专注接待 | 选择队列中的会话 → 阅读完整消息 → 编辑并发送回复 | 窄窗通过返回按钮回到列表 |
| 并排接待 | 在会话标题内固定到右窗、取消固定或更换固定会话；两窗分别滚动、切换回复 | 桌面并排展示，窄窗通过主接待／固定标签切换；取消唯一固定会话时回到主窗 |
| 卡片接待 | 只展示与左侧列表共用的最后一条消息摘要；点击回复展开编辑器，移出焦点收起 | 不再逐卡片预取历史；收起保留文字和附件草稿；完整对话按需分页；共用启动只读取摘要并把首位访客设为当前对象，不预取历史与资料，展开完整对话时才读取最近页；虚拟列表实现保留 |
| 消息历史 | 虚拟列表读取历史；向上加载较早消息；离开底部后可点击查看最新消息；消息时间默认隐藏，悬停或键盘聚焦时显示，隐藏常规回执 | 已接入真实 Server：首次展示完整对话（专注选中、并排任一侧、卡片展开）读取最近页，向上滚动用历史页 `nextCursor` 读取更早页，同页在途请求合并，空历史/到尾/失败重试都有明确展示；已初始化的访客切回直接复用缓存；重登后按库显示已受理消息与失败原因；非文本消息暂按「暂不支持的消息」展示 |
| 实时来信 | 坐席登录后建立 `/ws/desk` 长连接，来信直接出现在列表与已打开的对话中 | 已接入真实 Server：连接后先发 auth 报文，收到 ready 才读取初始数据（避免订阅与查询之间夹入的来信丢失），连接状态在右上角展示；message 报文按 ID/version 保护合并，其他端的回复也能直接新增到已加载的对话并更新左侧与卡片摘要；未打开的访客只更新摘要与状态（不建消息集合，首次打开仍取最近页）；摘要影响排序/计数视图时重读列表第一页与 counts；断线只上报状态，重连补齐与重查待后续实施票接入 |
| 待处理提醒 | 会话列表中的未读角标；进入会话读到底部后消除 | 已接入真实 Server：服务端不返回个人已读，提醒在本次运行的内存态维护——收到来信且该访客不在屏幕上（专注选中、并排固定或卡片展开）时计数，收到成功的 outgoing 结果或访客状态变为 waiting 时清除（其他坐席处理后同步消除）；登录或重连的初始化不制造旧提示，退出重登清空；读取到底部只清除本地提醒，不调用服务端 |
| 回复编辑器 | 插入表情、添加附件或选择快捷回复；插入后可继续编辑；发送并接待下一位 | 草稿按会话共享；接待下一位不会结束当前会话；完整刷新后草稿清空；已接入真实 Server：提交绑定提交时的访客与登录员工，本地先显示发送中气泡，受理后按同一消息 ID 合并；渠道失败显示真实原因并可对原访客/正文手动重试（新 `clientRequestId`，原失败记录保留）；纯文本以外的发送能力按渠道能力停用 |
| 来访资料 | 打开资料面板 → 查看渠道字段；复制全部渠道资料；维护标签和内部备注 | 复制包含渠道、账号、字段及来源身份；缺失与空值分别保留；修改和错误保留反馈 |
| 主题 | 主题菜单选择八套柔和配色，点击即时应用 | 极昼白、极夜黑、栗木红、麦穗金、草木绿、牛仔蓝、烟岚紫、亚麻褐；七套浅色共用中性灰阶、文字与访客气泡，极夜黑使用炭灰与灰色气泡；气泡不显示描边，选中会话无深色侧边条；旧主题偏好按相近色系恢复，三种模式共用 |
| 帮助与快捷键 | 顶部问号查看三种接待布局示意、快捷键和输入提示 | 响应式弹窗；支持键盘关闭 |
| 桌面宿主 | Tauri 标题栏拖动、最小化、最大化／还原、关闭 | Web 运行时隐藏原生窗口操作 |

## 共享关系

- 三种接待模式组合共享的会话标题、筛选工具、消息列表、回复编辑器与来访资料组件。
- 三种模式共用同一访客的消息集合与文字回复草稿：专注选中、并排主/固定窗与卡片展开只要展示同一位访客就复用已加载历史，不各自重查；并排固定会话在切换焦点后保持可用，切换访客不混淆消息与草稿。
- 并排的主接待、固定会话和当前回复对象由 inbox 状态管理；固定关系不会跨完整刷新恢复。
- 主题、接待模式和减少动态效果由本地偏好管理；账号、凭据及整个 store 不持久化。
- 渠道资料来自接待 API；复制不会把内部标签与备注混入渠道资料。

## 运行与验收边界

`VITE_DESK_MOCK=true` 显式启用模拟登录与会话数据，开发启动和打包测试使用相同的适配器；配置方法见 [Mock 打包测试](../../dudu-desk/README.md#mock-打包测试)。未启用时使用真实账户适配器、真实访客摘要适配器、按需历史适配器、文本回复适配器与实时通道（开发经 Vite 同源代理 `/api` 与 `/ws` 到本地 Server，打包用 `VITE_API_ORIGIN` 注入线上地址并派生 wss/ws 地址），不再使用模拟登录与会话数据；结束／继续、名片与附件准备仍为未接入方法，对应位置继续显示接待服务未连接的空态，待后续实施票接通。

纯文本发送只在 Server 已配置可发渠道账号时可操作（当前为配置了 `appId`/`appSecret` 的公众号账号）；能力为 restricted 时编辑器给出原因并停用发送与附件入口，发送端在服务端再校验一次。浏览器/双客户端人工核验（真实来信触发、两个 Desk 端同步、重启后按库显示）属 HITL，不在自动化测试范围内。
