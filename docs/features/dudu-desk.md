# DuduDesk 功能图谱

记录当前前端工作台的功能、入口与限制。子项目概览见 [DuduDesk README](../../dudu-desk/README.md)，当前接口边界见 [InboxApi](../../dudu-desk/src/features/inbox/api.ts)，后端对接实施依据见已定稿的[最小契约](../design/dudu-desk/implementation-contract.md)；企业登录、访客摘要列表、按需对话历史、实时来信订阅、纯文本回复、结束／继续接待、共享名片、全部消息类型的展示及媒体查看、权限变更重载与断线重连重新加载已接通，附件准备尚待逐项接通

2026-10-13 移除 Mock 模式：删除 `VITE_DESK_MOCK` / `VITE_DESK_SCENARIO` 开关、开发适配器与固定数据工厂、调试场景及相应测试，应用恒走真实适配器；stores 与组件测试共用的测试夹具迁入 `dudu-desk/src/features/inbox/test-fixtures.ts`。下文历史条目中的 Mock 表述自即日起失效，以本条移除记录为准

2026-10-13 审查修复（双轴审查结论落地）：失败气泡重试不再只认本次运行的本地提交——重试优先用本地提交，缺失时（重登或他端加载的失败消息）从消息自身取原访客与正文生成新的 `clientRequestId` 调同一发送接口，原失败记录保留、当前草稿不被占用；重新登录后按库展示的 `sending` 受理记录显示「发送中」，failed/unconfirmed 的提示与重试入口不变；delivery 解析收紧到契约三态 `sending/sent/failed`，契约外取值（accepted/delivered/read/unconfirmed）在真实报文里按无效响应拒绝，Mock 世界仍用自身词表；结束接待（closed）与其他端一致地清除本端待处理提醒，较新的待回复状态不被较旧的结束报文误清，重连补回已结束的访客不重建提醒

2026-10-13 断线重连重新加载接通：真实实时通道在掉线后按退避自动重连（1 秒起、逐次翻倍、上限 15 秒），重新认证并在 ready 后再次上报 connected；认证被拒（登录状态无效）或订阅被释放后不再重试，重连期间界面沿用「正在连接接待服务」状态并保留手动重连入口。重连成功后执行同一初始化查询，不新增恢复专用接口、事件重放或差量对账：先递增范围代数让旧代数的在途请求全部失效（迟到的读取结果不写回），重查身份/权限（与 access-changed 共用同一链路，清理已无权数据），重读访客列表第一页与计数；旧历史缓存失效并重置 hasLoaded——正在显示的访客重取名片与最近消息页（新最近页替换旧缓存而不是拼接，更早消息从新页游标照常向上分页），其他访客切回时按需重取；发送结果、名片与接待状态直接取查询结果，补回的旧消息不制造提醒、已处理事项不重新提醒（本地提醒按重查结果清除服务端已等待中的访客）。临时断线保留仍有权访客的文字与名片草稿及「资料已被更新」覆盖提示，退出重登仍清空运行缓存与提示；Mock 开发世界保留自身游标字段，重连同样走重查

## 功能与入口

2026-10-12 权限变更与工作区清理接通：真实通道的 access-changed 报文（只有 type）触发工作区重载——先递增范围代数让旧代数发起的请求全部失效（迟到的读取结果不写回新范围），取消在途读取后重查身份（`GET /api/desk/profile`）取回当前授权账号集合，清理已无权的对话及其消息、历史、名片、资料编辑、回复草稿、固定与提醒（被清理对象正是当前选中/固定会话时沿用 removed 事件提示重新选择，附件预览一并回收），仍有权数据原样保留；随后重查列表第一页与计数，按新范围展示，队列为空时沿用现有空态；身份未能确认（刷新失败或已退出）时不清理数据、只重查列表。实时订阅跟随连接生命周期，不因范围变化重建；退出与切换员工按既有流程销毁工作区与订阅，迟到结果不进入下一名员工的工作区

2026-10-12 全类型消息与媒体查看接通：真实适配器按契约第 4 节解析全部消息体分支（text/image/audio/video/file/reply/link/location/quote/card/unknown），渠道未提供的可选字段（媒体 name/mimeType/size/url）省略并回落到类型名与「大小未知」，契约之外的渠道类型继续按「暂不支持的消息」展示；媒体展示：有公开链接的素材由桌面端直连渠道，只有渠道标识的素材经 `GET /api/desk/messages/{messageId}/media?index=N` 以已有认证请求取 Blob 后再展示/打开（JWT 只出现在请求头，不进图片 URL），单媒体消息 index=0、reply 按 attachments 下标，加载失败沿用「素材暂不可读取」提示，每个「消息:下标」只请求一次且随工作上下文重置回收对象 URL；历史、实时与重登共用同一消息体解析与组件，左侧列表与卡片继续只取服务端摘要，完整对话仍按需分页，虚拟滚动写法未改；Mock 场景对只有渠道标识的媒体由适配器按引用合成字节（音频为可复现的静音 WAV，视频等为声明类型的占位字节，无法解码时沿用失败提示），Mock 数据与真实路径共存

2026-10-12 共享名片接通：真实适配器已接 `GET/PUT /api/desk/visitors/{visitorId}/profile`（读取返回 conversationId/version/fields/tags/note，保存只发 tags 与 note），渠道资料三态（有值／内容为空／渠道未提供）原样展示与复制；realtime 的 profile 报文按 version 保护合并——未编辑时当前面板即时刷新（不必切换访客），编辑中保留本地输入并标记「资料已被更新」，保存前提示一次是否覆盖（确认后普通保存、后保存覆盖，取消显示最新服务端资料）；保存响应与较旧详情都不回退较新资料，保存响应不清空提交之后继续输入的草稿，撤销编辑显示最新服务端资料；名片保存不当作消息活动，仅在当前搜索视图下重读列表

2026-10-12 结束／继续接待接通：真实适配器已接状态接口（`PUT /api/desk/visitors/{visitorId}/status`，只收 `closed` / `needs-reply`），结束／继续按钮沿用既有组件与确认流程，成功后按 HTTP 返回与 Socket conversation 报文版本保护合并；各模式、状态筛选与计数按后端结果同步，结束后来信由服务端重新转为待回复并直接入列，固定会话与未发送草稿保留

2026-10-12 纯文本回复接通：真实适配器已接发送接口（`POST /api/desk/visitors/{visitorId}/messages`）与回复能力（会话对象与 `GET …/capability` 同源），发送中本地先显示气泡，HTTP 返回与 Socket 通知按同一消息 ID 合并为一条，渠道失败也按已保存的失败气泡展示真实原因并保留手动重试；附件准备/上传/发送延期，已收到的非文本内容继续展示，真实适配器下选择/粘贴/拖拽入口按能力停用（不伪装可用），Mock 场景按自身能力数据保持可用

## 共享关系

- 三种接待模式组合共享的会话标题、筛选工具、消息列表、回复编辑器与来访资料组件
- 三种模式共用同一访客的消息集合与文字回复草稿：专注选中、并排主/固定窗与卡片展开只要展示同一位访客就复用已加载历史，不各自重查；并排固定会话在切换焦点后保持可用，切换访客不混淆消息与草稿
- 并排的主接待、固定会话和当前回复对象由 inbox 状态管理；固定关系不会跨完整刷新恢复
- 主题、接待模式和减少动态效果由本地偏好管理；账号、凭据及整个 store 不持久化
- 渠道资料来自接待 API；复制不会把内部标签与备注混入渠道资料

## 运行与验收边界

真实适配器为唯一实现：真实账户适配器、真实访客摘要适配器、按需历史适配器、文本回复适配器、共享名片适配器、结束／继续状态适配器、消息媒体适配器与实时通道（开发经 Vite 同源代理 `/api` 与 `/ws` 到本地 Server，打包用 `VITE_API_ORIGIN` 注入线上地址并派生 wss/ws 地址）。附件准备仍为未接入方法，对应位置继续显示接待服务未连接的空态，待后续实施票接通

纯文本发送只在 Server 已配置可发渠道账号时可操作（当前为配置了 `appId`/`appSecret` 的公众号账号）；能力为 restricted 时编辑器给出原因并停用发送与附件入口，发送端在服务端再校验一次。媒体读取同样只对已接入渠道可操作：公开链接（公众号图片 PicUrl）由桌面端直连，需渠道凭据的素材依赖 Server 的公众号凭据与素材接口；公众号语音为 8K amr，浏览器与桌面 WebView 多数不能直接播放，当前不做转码，会落到「素材暂不可读取」提示；渠道素材过期由服务端如实返回渠道错误，界面沿用同一失败提示，不做自动重取。浏览器/双客户端人工核验（真实来信触发、两个 Desk 端同步、媒体实际播放/打开、管理端迁组/退组后两端的范围收敛与清理、断开再连接后列表/当前对话/名片/权限/草稿的重载、重启后按库显示）属 HITL，不在自动化测试范围内

## AI 悬浮助手（2026-10-26）

专注、并排、卡片模式共用真实模型助手，按当前回复对象读取授权会话上下文，支持摘要、拟回复、润色、连续追问、停止生成、失败重试和内部问答重建

采纳写入当前对象的真实草稿，经编辑后沿用现有发送链路；草稿未再次编辑时可撤销，切换对象或权限代数变化时不覆盖旧目标，卡片完整对话内保留可访问入口和焦点范围

初始企业管理员独立配置助手使用的通用模型，未启用时显示指引；问答只保留在本次工作区，权限范围变化和退出时取消并清理，不生成虚构知识库引用
