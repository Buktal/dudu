# MockPulse 事件流交互原型

入口：[mockpulse-debugger.html](./mockpulse-debugger.html)。本轮只保留用户选定的 **方案 3：事件流**，已移除另两个方案及切换入口

单文件 HTML / CSS / JavaScript，无依赖安装、构建、服务或远程资源。所有请求与回执均为演示

早期 Studio 版原型的界面与交互记录见 [MockPulse Studio 记录](mockpulse-studio-notes.md)

## 打开与试用

在资源管理器中使用 Edge 或 Chrome 直接打开 HTML，或将文件拖入浏览器。已经打开旧版时，请刷新页面

如果编辑器内嵌预览提示 `file:` 安全源错误，请直接用浏览器打开文件。页面不使用 iframe、不读取其他本地文件；在 `file:` 下导航只更新当前文件的 hash，不调用 History API

建议按下面的流程试用

1. 在事件调试中，选择默认抖音事件。搜索“用户”或“头像”，修改发送者 ID、用户资料和头像地址；聚焦字段即可查看含义，也可以切换到 JSON
2. 修改事件名称，点击“保存”。从右上角“…”选择“另存为”，可以生成独立配置；原剧本继续引用原事件
3. 进入平台剧本，选择同平台的已保存事件，点击“添加”。可以重复引用同一个事件，用上下按钮排序；每步也能单独发送
4. 从剧本步骤点击编辑原事件，修改参数并保存，再运行剧本，检查采用的新版本
5. 在运行编排组合抖音和企业微信剧本，分别试用串行、并发及停止。侧栏“原型选项”中可以选择正常应答、签名被拒绝或等待超时
6. 在“原型选项”中开启容量演示，检查 20 平台、400 事件、60 剧本下的搜索、分页和平台切换。点击“返回我的数据”恢复进入演示前的事件库和草稿

快捷键：`Ctrl / Cmd + Enter` 发送当前事件；`Ctrl / Cmd + S` 保存当前页面的事件、剧本或编排

## 已确认的三层模型

确认日期：2026-09-11。用户明确选定事件流，并进一步确认保存事件作为复用单元

| 层级 | 保存内容 | 主要行为 |
| --- | --- | --- |
| 已保存事件 | 平台、事件类型、名称、标签、完整载荷、附加请求头、期待回执 | 完整参数编辑、字段说明、保存、另存为、独立发送。消息和事件使用同一套编辑方式。 |
| 平台剧本 | 固定平台、名称、有序的已保存事件引用 | 从同平台事件下拉列表添加，用按钮排序、移除或单独发送，保存并顺序运行。 |
| 运行编排 | 名称、执行方式、有序的剧本引用 | 可跨平台组合多个剧本，串行等待前一个完成，或并发启动。每个剧本内部始终按顺序运行。 |

例如：抖音剧本只能选择抖音的已保存事件；企业微信剧本只能选择企业微信事件。抖音 A 和企业微信 A 可以在运行编排中共同执行。平台隔离也在添加动作和导入校验中检查

既有平台约束见 [ADR-0004](../../adr/0004-script-per-platform.md)。本轮新增明确了事件保存与引用、完整参数编辑，以及大数量下的布局

## 页面布局

| 页面 | 本轮设计 |
| --- | --- |
| 事件调试 | 标题旁选择平台。左侧搜索、筛选和翻页；右侧用两列表单编辑参数，主要操作为保存、发送。“…”收纳另存为、导出事件和字段定义。回执压缩到底部，最近请求默认折叠。 |
| 平台剧本 | 在页面标题旁选择平台。左侧查找剧本，右侧显示有序步骤；下方通过“搜索 + 下拉列表 + 添加”引用已保存事件。只实现加号方式，没有拖拽。 |
| 运行编排 | 左侧排列剧本，以简洁的串行 / 并发按钮选择执行方式；右侧搜索和添加剧本。执行时显示各剧本的进度与结果。 |
| 运行记录 | 搜索并按平台、结果筛选，分页查看运行快照；旧记录可作为新事件重新编辑。 |
| 连接设置 | 在连接表单中独立选择要配置的平台并修改接收地址；导入、导出事件库；切换浅色与深色外观。 |

工作区采用全窗口布局，用留白、对齐和浅色填充区分侧栏、列表与编辑区。移除外框、顶栏面包屑、英文小标题、重复说明与常驻演示工具条；参数行和步骤行不画分隔线。蓝色突出发送和运行操作。字段帮助、步骤的编辑与排序按钮在悬停或键盘聚焦时显现；触摸设备直接显示这些操作

平台选择位于事件调试与平台剧本各自的标题旁。两页共用最近选定的平台，方便保存事件后继续组装剧本

运行编排和运行记录默认跨平台展示，页内的平台筛选各自独立。连接设置单独记住要配置的平台；切换或应用连接配置会保留正在编辑的事件、未保存参数和剧本选择。各平台尚未应用的地址也分别保留在本次会话中。事件编辑器旁的“连接设置”快捷入口会明确打开该事件所属平台的配置；应用后留在设置页

## 完整参数与字段说明

编辑器展示“字段 / 当前值”两列。字段名下保留参数路径；聚焦输入框或点击说明按钮时，编辑区下方只显示当前字段的含义、类型及固定值等信息。可以点击关闭或按 Escape 收起，焦点留在相应参数。搜索、切换事件或切换编辑页签时会收起旧说明

支持文本、数字、布尔值、枚举、嵌套对象、数组增删，以及缺失字段的添加。搜索同时匹配字段路径、中文标题和说明。“…”中的“字段定义”提供定义来源和完整 Schema

表单由平台事件定义驱动，不为每个事件单独编写页面。定义采用 JSON Schema 风格的数据，包含 `type`、`title`、`description`、`default`、`const`、`enum`、`properties`、`items`，并补充分组、版本及来源链接。这里实现的是原型所需的编辑与基础校验，不是完整 JSON Schema 引擎

新增平台仍然需要依据官方协议补充字段含义；这些信息属于平台定义数据。未收录的字段保留原值，允许在表单和完整 JSON 中编辑，查看说明时会提示“未收录字段说明”

完整 JSON 包含三个对象：`payload`（完整事件载荷）、`headers`（附加请求头）、`expect`（期待回执）。表单与 JSON 相互转换时保留扩展字段；保存和发送都会检查 JSON、字段类型和期待设置

内置抖音样例包含发送者、接收者、应用标识、会话、时间，以及 `user_infos` 中各用户的 ID、昵称和头像。进入私信事件的 `content` 在编辑时展开为对象，在请求预览中按平台规则序列化为 JSON 字符串

企业微信自建应用回调使用其实际明文字段；它本身不包含用户昵称与头像，编辑器不会把这些字段冒充为平台字段。`MsgId` 按字符串保留，避免 64 位 ID 精度丢失。请求预览同时展示完整明文与演示加密外层

## 参数复用与执行快照

剧本步骤保存 `eventId` 引用。原事件保存新参数后，后续运行会采用新版本；“另存为”创建新事件，不改变现有剧本引用

每次开始运行时，先解析所有剧本、所有步骤的已保存事件，并固定全部参数与目标地址。运行期间修改或保存事件，不影响当前任务；未保存的事件编辑也不会悄悄进入剧本运行

当前原型的失败策略是停止失败的剧本，其他剧本继续执行。HTTP 状态、耗时和期待检查分别记录：HTTP 200 不自动等于测试通过，也不表示业务处理成功

## 数量增长

| 对象 | 查找与呈现方式 |
| --- | --- |
| 平台 | 事件调试与平台剧本在页内提供可搜索的平台选择器；平台列表在弹窗内滚动。连接表单使用独立的配置平台选择。 |
| 已保存事件 | 默认当前平台；可切换全部平台，按名称、事件类型、标签或平台名称搜索，并按消息 / 事件筛选。每页 10 项。 |
| 平台剧本 | 默认当前平台；支持跨平台搜索和每页 10 项。选中跨平台条目时保留列表页码。 |
| 编排的候选剧本 | 搜索、平台筛选、每页 10 项；已选剧本独立显示。 |
| 参数、步骤与日志 | 各自滚动，避免内容数量撑长整个桌面页面；窄屏改为纵向排列。 |

容量演示生成 **20 平台 × 20 事件 = 400 个事件，20 平台 × 3 剧本 = 60 个剧本**。其中抖音与企业微信使用当前样例定义，其余 18 个是明确标注的虚拟平台，不代表已经接入它们的真实协议

容量演示与正常事件库隔离。进入时保留事件库和草稿，退出时恢复；演示中的保存不写入正常数据。演示数据的导出带有标记，只能在容量演示模式中重新导入

## 保存与导入导出

- 保存的事件、剧本、编排使用当前浏览器的 `localStorage`，键名为 `mockpulse.prototype.debugger.v2`。事件需要明确点击保存；剧本的添加、排序和移除会自动保存，也保留“保存剧本”按钮；编排明确保存后持久化
- 上版 `mockpulse.prototype.debugger.v1` 剧本会迁移为已保存事件与引用关系；原存储键仍保留。需要修正的旧参数可以继续载入编辑，在发送或保存时校验
- 切换事件或平台会保留本次会话的未保存编辑。运行记录、未保存草稿、连接地址和外观设置不保证跨刷新恢复
- 若浏览器禁止本地存储，会显示说明；仍可编辑并导出备份。不同浏览器、文件位置或预览宿主不保证共享存储
- 导出格式包括 `mockpulse-event-v2`、`mockpulse-script-v2`、`mockpulse-library-v2`。剧本导出携带其引用的事件，完整事件库携带全部引用关系；导入时生成新 ID，不覆盖同名条目。仍支持上版 `mockpulse-prototype-v1` 剧本
- 这些是交互原型的数据格式。正式执行契约仍需依据产品规格确定；原型可将已解析步骤投影为 `channel / event / content / expect` 四项数据
