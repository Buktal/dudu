# DuduDesk · 接待原型探索

用于讨论消息接待方式的可交互原型。只使用模拟消息，所有操作都发生在本地内存；刷新或「恢复初始演示」会清空本次修改

## 打开

直接双击 `dudu-desk-prototype.html`。这个单文件已内嵌脚本、样式和字体，不需要安装依赖

需要修改原型时，在本目录运行

```powershell
yarn dev
```

访问 <http://127.0.0.1:4317/>，底部切换方案。也可直接打开

- [1 自在](http://127.0.0.1:4317/dudu-desk-prototype.html?variant=A)
- [3 并肩](http://127.0.0.1:4317/dudu-desk-prototype.html?variant=C)

URL 参数使用 `A / C / D / E`，界面编号沿用用户反馈中的 `1 / 3 / 4 / 5`。修改源码后运行 `yarn build`，重新生成单文件

## 本轮方向

| 方案 | 组织方式 | 希望验证的操作体验 |
| --- | --- | --- |
| 1 自在 · 保留 | 会话列表、聊天区、访客资料 | 熟悉的聊天布局，频繁切换时是否顺手 |
| 3 并肩 · 保留 | 主接待 + 手动固定一位访客 | 等待一位补充信息时，继续处理另一位 |
| 4 折页 · 保留 | 在访客所在行展开完整聊天 | 名单与聊天保持同一个位置，减少寻找窗口 |
| 5 速答 · 保留 | 每位访客一张最新消息卡，卡内直接回复 | 简单咨询可否就地完成，复杂问题再展开上下文 |

用户认可四版的基本设计，当前倾向提供「经典界面 + 快速响应模式」，候选是 1 + 3 或 1 + 5，尚未选择最终组合。2「接力」已淘汰，四个现有方向继续保留比较

### 本轮：品牌、圆角和操作反馈

四版统一使用嘟嘟橙，搭配薄荷绿、奶杏色与淡紫；侧栏朝聊天区的一侧使用大圆角。选中访客和方案的底色滑动跟随，资料栏平滑收放，快捷回复、完整对话、发送消息都有短过渡

使用 MagicUI 的 RippleButton、BlurFade、NumberTicker，复用项目已有的 Motion。动效发生在操作时，并适配系统的减少动态效果偏好。没有新增依赖

现有「表情 D」Logo 的轮廓与 U 形眼睛保持不变，原样用于导航、横版品牌位与 favicon。具体取舍见 [本轮设计记录](design-polish.md)

### 3 的双窗规则

左窗是主接待，点击会话列表会在这里切换访客。右窗是手动固定的访客；列表切换不会替换它，点击已固定的访客会直接聚焦右窗

「更换固定访客」和会话行上的「并排打开」负责选择右窗。可以「收起第二窗」，需要时再「添加并排对话」。每位访客都有自己的草稿，收起窗口不会删除草稿；侧栏跟随当前回复对象

### 4 的位置规则

一次展开一段聊天，点击另一行便切换。发送回复时，列表保持原有位置；主动更改排序选项时才重新排序。聊天区可独立滚动，清单也可独立滚动。收起对话后可快速浏览整张清单

### 5 的卡片规则

每位访客只有一张卡，内容取自真实的演示消息记录：最新来信、上次回复，不生成摘要。新消息更新原卡，卡片顺序保持稳定

每张卡的输入框固定回复给这位访客。点头像查看侧栏资料，点「完整对话」查看历史、图片、语音文字和附件，使用完整输入区。卡片与完整对话共享草稿

## 可体验的交互

- 切换方案、访客、来源筛选与搜索；状态筛选、星标（方案 1、3）
- 文本发送、快捷回复、表情、示例图片；部分渠道提供示例文件入口
- 快捷回复和表情面板支持 Esc、点击外部收起；搜索入口会展开隐藏的会话列表并聚焦
- 每位访客独立草稿；切换方案后继续编辑
- 双窗手动固定、更换、收起和恢复；输入对象与侧栏联动
- 访客标签和接待备注，跨方案保留
- 「体验场景」模拟新消息、发送失败与重试、回复窗口受限和恢复
- Enter 发送，Shift + Enter 换行，Ctrl + Enter 发送后接待下一位，Ctrl + K 搜索，Alt + 1 / 2 选择并行窗口

示例中包含两位不同来源的「林小满」；她们的身份、草稿、标签与备注各自独立。统一访客类型不代表自动合并跨渠道身份

## 设计范围

仅探索消息收发和访客信息。渠道、店铺账号和回复资格仍然可见；来源不改变通用消息的展示方式。缺失的头像、电话、地区明确降级，发送成功不冒充送达或已读。商品详情为手写演示数据，不表示渠道接口会自动提供完整商品资料

资料依据见 [统一消息体验约束](../../research/dudu-desk/experience-constraints.md)。这些布局是设计假设；尚未进行真实坐席效率或市场验证

视觉侧重点：1 的浅色三栏、3 的薄荷绿双窗、4 的暖白展开清单、5 的淡紫消息卡。交互结构承担差异，来源徽标与消息样式保持一致。中文正文使用系统 UI 字体，英文与数据使用本地 Inter，品牌字标使用现有 SVG 自绘路径
