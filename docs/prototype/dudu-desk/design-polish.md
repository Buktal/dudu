# DuduDesk：让接待界面更轻快

本轮问题：保留已认可的接待布局，能否通过品牌、配色、圆角和操作反馈，让长时间接待更舒适，让切换和回复更自然

用户当前倾向 1 + 3 或 1 + 5，提供一款经典界面和一款快速响应模式。最终组合尚未确定，本轮继续保留 1、3、4、5

## 视觉选择

| 部位 | 处理 | 原因 |
| --- | --- | --- |
| 品牌 | 现有表情 D、U 形眼睛、自绘 DuDu 字标 | 已经有温和、活泼的识别点，先建立产品中的统一使用方式 |
| 主色 | 信号橙 `#F2673C`，发送按钮使用更深的 `#C74B27` | 品牌有活力，白字操作按钮保留可读性 |
| 辅色 | 薄荷绿 `#DCF1DE`、淡紫 `#EEE8FA`、浅杏 `#FFEBD9` | 区分区域和模式，降低深色大块区域的压迫感 |
| 字色与底色 | 深墨绿灰 `#333B37`、浅底 `#F5F7F5` | 消息正文与装饰层次分开，保留阅读对比 |
| 左侧会话区 | 朝聊天区的一侧使用 28–30 px 圆角 | 从硬边分栏变成轻柔的区域分隔 |
| 右侧资料区 | 左上、左下圆角；头像块、资料块和备注分层 | 一眼认人，再按需要读资料 |
| 输入区与气泡 | 圆润输入容器，浅杏发出气泡，清楚标出回复对象 | 统一跨渠道消息样式，保留发送目的地 |
| 标签 | 淡紫、浅杏标签；移除按钮在悬停或聚焦时更明显 | 保留可编辑能力，降低默认状态的干扰 |

1、3 不再用深蓝色作为大面积底色。3 用薄荷绿画布，5 用淡紫画布；品牌与发送操作统一为橙色。颜色承担区域识别，接待方式仍由布局和操作规则决定

## 操作反馈

- 会话行、状态筛选和底部方案切换：选中底色滑动到新位置
- 访客资料：侧栏宽度平滑变化，内容短距离淡入；收起后不可通过键盘误入隐藏内容
- 消息与弹层：新消息轻量入场；快捷回复、表情、图片预览、完整对话和说明弹层淡入淡出
- 发送：MagicUI RippleButton 提供点击涟漪，已有的发送中、成功与失败状态继续展示
- 数量：MagicUI NumberTicker 用于待回复等计数，初始值直接显示，避免进入页面时从零滚动
- 资料与会话切换：MagicUI BlurFade 提供短距离过渡；接收方和输入框及时切换，不等待动画结束
- 系统减少动态效果开启时，关闭布局移动与 CSS 过渡；数字直接呈现，淡入不产生位移或模糊

主要区域与弹层使用约 160–260 ms 的过渡，发送涟漪为 480 ms。动画不驱动发送逻辑，也不延迟输入和点击

## 顺手修正的细节

搜索按钮和 Ctrl + K 会先展开会话区，再聚焦搜索框；窄窗口的星标入口也会展开名单。速答卡点击头像会打开这位访客的资料，输入框聚焦只切换回复对象。快捷回复和表情面板可用 Esc 或点击外部收起

适当增大来源标签、列表文字与部分按钮的可点击范围。右侧资料独立滚动；窄窗口改为抽屉。并肩模式在窄窗口使用主接待/固定访客切换，收起第二窗后仍能继续主接待

## Logo 判断

本轮不修改 Logo 几何。现有 D 形气泡、两只开口向上的 U 形眼睛与消息产品一致，橙色也适合作为互动反馈的主色

使用品牌目录 `docs/brand/emoji-d` 的原始 SVG：完整横版至少 168 px 宽，紧凑导航用独立图形，浏览器图标用专门的 favicon 版本。三份原型副本均已校验哈希与原图一致

## 实现与验证

仅修改 `docs/prototype/dudu-desk` 内的原型。复用 Desk 已安装的 Motion、Base UI/shadcn Button 和工具链，无新增依赖

MagicUI 的三份源码来自官方注册表，通过 `shadcn view @magicui/blur-fade @magicui/number-ticker @magicui/ripple-button` 查看并导出，原始返回保存在 `magicui-registry.json`。源码保存在 `src/components/magicui`，上层组件负责外观、组合与减少动态效果适配

通过 lint、TypeScript 和单文件构建；检查 1440 × 900、1280 × 720、390 × 844。验证侧栏与弹层、草稿保留、模拟发送、失败重试、双窗固定与恢复、折页顺序、速答完整历史、头像资料和搜索入口。生成的独立 HTML 通过本地 HTTP 预览，控制台无错误或警告

这些原型用于选择和打磨交互方向。最终组合、长期坐席体验及效率仍需用户实际体验后确认
