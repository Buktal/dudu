# MockPulse 前端交互原型

入口：[mockpulse-debugger.html](./mockpulse-debugger.html)。

这是一次从调试任务重新设计的原型，不沿用旧控制台布局。单文件 HTML / CSS / JavaScript，无依赖安装、构建、服务或远程资源。

## 打开

在资源管理器中使用 Edge 或 Chrome 直接打开 HTML 文件，也可以将文件拖入浏览器窗口。

若编辑器内嵌预览出现 file: 安全源错误，请改用浏览器直接打开。原型不使用 iframe，也不读取其他本地文件；在 file: 下切换布局和页面只更新当前文件的 hash，不调用 History API。

底部原型条用于切换布局、选择演示回执、查看完整状态和设计说明。

## 本轮用户明确确认的需求

确认日期：2026-09-10。以下为产品行为要求；具体视觉布局仍待用户评审。

| 层级 | 操作单元 | 行为与约束 |
| --- | --- | --- |
| 单条调试 | 一个事件或一条消息 | 先选平台，再选该平台的事件或消息；编辑内容和期待回执；可独立发送，也可加入同平台剧本。 |
| 平台剧本 | 同一平台的一组有序步骤 | 剧本固定属于一个平台。抖音剧本不能选择企业微信事件，反之亦然。剧本可创建、编辑、保存、导入和导出。步骤可单独发送，也可按顺序运行整个剧本。 |
| 运行编排 | 多个剧本 | 可以跨平台组合，例如抖音 A 与企微 A；支持串行或并发执行。串行按列表顺序等待前一个剧本结束；并发同时启动各剧本。单个剧本内部仍按步骤顺序执行。 |

已有 ADR-0004 记录了平台隔离与跨平台并发。本轮进一步明确了单条发送、剧本保存、逐步独立发送，以及多个剧本的串行执行。此处完整记录这些新增要求，供后续正式规格承接。

## 界面如何从任务推导

用户打开工具，需要尽快回答三个问题：

1. 模拟的平台会发送什么内容？
2. 我的服务是否给出了 HTTP 应答？
3. 应答是否满足本次测试设置的期待？

因此首页直接进入单条调试，请求输入和回执结果并排。HTTP 状态、耗时、期待检查分别呈现；HTTP 200 不自动等同于测试成功，更不等同于业务处理成功。

| 页面 | 主要用途 |
| --- | --- |
| 事件调试 | 选择平台与事件，编辑内容，独立发送，对照请求和回执，将当前事件加入剧本。 |
| 平台剧本 | 管理本平台的步骤，增删、编辑、调整顺序、逐步发送、保存和运行。 |
| 运行编排 | 引用已有剧本、调整顺序、选择串行或并发、保存编排、观察每条执行线。 |
| 运行记录 | 按平台、结果或关键词筛选；查看包含来源路径的请求与回执快照；将旧事件载回调试台。 |
| 连接设置 | 分平台配置待测服务地址和演示身份；调整外观。 |

事件选择器、添加步骤和导入校验都执行平台约束。跨平台组合只发生在运行编排中。

## 三个可对比的调试布局

- **并排调试（默认推荐）**：构造事件与检查回执同时可见，适合反复修改和对照。
- **分步调试**：选择平台、构造事件、确认请求、检查回执四步展开，适合首次使用。
- **事件流**：快速发送栏、运行列表和详情同时呈现，适合连续发送与回看。

三个布局共用相同的平台规则、剧本和运行记录。其他四个页面保持一致。

可以用 ?variant=split、?variant=guided、?variant=stream 指定初始布局。在本地文件中切换后，布局和页面保留在 URL 的 hash 中。方向键也可切换，输入控件获得焦点时不拦截方向键。

## 建议按这个顺序试用

1. 在事件调试发送默认抖音文本私信，查看概览、响应体和请求详情。
2. 将期待状态码改为 204，再发送一次，观察“收到了 200”与“符合期待”的区别。
3. 点击“加入平台剧本”，保存到抖音剧本；进入平台剧本，编辑步骤并检查事件选择器。
4. 创建企业微信剧本，确认可选择的事件已切换为企业微信。
5. 在运行编排选择抖音 A 与企微 A，分别尝试串行和并发。执行线应呈现不同的启动顺序。
6. 在底部选择“签名被拒绝”或“等待超时”，重新运行；查看失败停止位置和运行记录。
7. 保存剧本与编排，刷新页面确认仍可载入；导出 JSON 后再导入，检查内容。

内置示例：抖音 A 为 3 步，企微 A 为 2 步；默认跨平台编排包含这两个剧本。

## 保存与原型边界

- 显式保存的剧本和编排保存在当前浏览器的 localStorage，键名为 mockpulse.prototype.debugger.v1。
- 浏览器禁止本地存储时会显示说明；可通过导出 JSON 保存剧本。浏览器、文件位置或预览宿主改变时，不保证共享同一份存储。
- 运行记录、未保存的编排草稿和连接配置仅保留在本次打开期间。真实密钥不写入原型的持久化数据。
- 导出的剧本是原型格式 mockpulse-prototype-v1。文件级声明所属平台，每步有 channel、event、content、expect 四个字段。content 包含模拟发送者和平台事件载荷，以保证导出再导入不会丢失编辑内容。此格式不代表正式后端契约已经定案。
- HTTP 应答、签名、加密载荷和耗时均为演示数据。没有真实网络请求、密码学运算、平台接入或自动重试。
- 当前原型规则：某步失败时停止所在剧本；其他剧本继续，最终汇总结果。这是待确认的执行策略。
- 原型用于评审信息结构与操作流程；正式前端仍需依据确定后的规格实现。

## 为什么这轮用 HTML

这轮需要验证平台隔离、从事件组装剧本、保存、执行顺序和结果反馈。可点击的 HTML 可以直接验证这些行为。Figma 更适合后续视觉规范、标注与设计协作交接。
